# Folduct 웹앱 Cursor 시작 안내

이 묶음은 Folduct의 새 방향인 **중단한 작업의 맥락을 되찾는 웹 작업공간**을 구현하기 위한 지시서다. 대상은 기존 `apps/web`이다. 이 지시서 작성 시점에는 구현 작업을 시작하지 않았다.

## 1 Cursor에서 열 폴더

`memory-desk` 폴더 전체를 Cursor에서 연다. `apps/web`만 열면 기획서와 인수인계 문서를 찾기 어려우므로 저장소 전체를 연다.

이하 모든 코드 경로와 프롬프트 경로는 `memory-desk`를 기준으로 한다. 다른 컴퓨터에서도 같은 폴더 구조를 유지하면 된다.

## 2 읽을 문서

1. [프로젝트 기획서](../../docs/folduct-project-plan-v1.0.md): 문제, 사용자, 제품 가치와 검증 목표.
2. [PRD 2.0](../../docs/folduct-prd-v2.0.md): 기준 문서. 하나의 컨셉, 제품 기준, FR15~19·AC28~38과 1.0 변경점.
   [WEB PRD 1.0](../../docs/folduct-web-prd-v1.0.md): FR01~14, 인수 기준 AC01~27의 세부 규칙.
   [방 돌보기 구현 지시서](../../docs/cursor-room-care-prompts.md): C0~C7 단계별 프롬프트(실제 파일을 정리 상자 폴더로 옮기는 기능).
3. [단계별 구현 지시서](01-build-steps.md): 실제 개발 순서와 단계별 복사 프롬프트.
4. [진행 기록](02-progress.md): 다음 대화에서 이어갈 근거와 미완료 사항.
5. [인수 검증표](03-acceptance.md): 테스트 결과와 미검증 상태.
6. [Vercel 배포 지시서](04-vercel-deployment.md): 10단계 배포 준비와 별도 승인 후 Preview·운영 배포.

요구사항의 기준은 새 WEB PRD다. 단계별 지시서는 PRD를 개발 순서로 나눈 것이며 P0 범위를 축소하지 않는다. 서로 충돌하거나 구현상 빈틈이 발견되면 근거와 해결안을 진행 기록에 남긴다. 실제 제품 범위나 데이터 보존 의미를 바꾸는 결정은 사용자에게 알린다.

`handoff/cursor-final-prompt.md`, `docs/spatial-archive-final-prd.md`와 `apps/desktop`은 이전 방향의 자료다. 이번 구현에서 Tauri, 4 Wall, 데스크톱 앱 전용 API를 가져오지 않는다. 과거 문서와 사용자 파일을 삭제하지 않는다.

## 3 처음 붙여 넣을 프롬프트

아래 내용을 Cursor Agent에 그대로 붙여 넣는다.

```text
이 저장소의 Folduct 웹앱을 새로운 기획에 맞춰 단계별로 구현할 거야.

먼저 다음 문서를 순서대로 읽어줘.
1. docs/folduct-project-plan-v1.0.md
2. docs/folduct-web-prd-v1.0.md
3. handoff/cursor-web-v1.0/01-build-steps.md
4. handoff/cursor-web-v1.0/02-progress.md
5. handoff/cursor-web-v1.0/03-acceptance.md

대상은 apps/web의 React + TypeScript + Vite 웹앱이야.
제품의 중심은 폴더 연결, 자료 배치와 이유 메모, 여기서 멈추기, 재방문 이어가기야.
이전 Tauri 앱이나 4 Wall 기획으로 구현하지 마.

지금은 01-build-steps.md의 0단계만 실행해줘.
기존 코드와 변경 상태를 확인하고 기준 빌드 결과, 재사용할 부분, 새로 만들 부분,
PRD 충돌이나 미정 사항을 02-progress.md에 기록해줘.
기존 사용자 변경을 보존하고, 앱 기능을 먼저 갈아엎지 마.
기준 빌드 실패가 있으면 원인과 이후 작업의 관계를 구분해서 보고해줘.

검증하지 못한 항목은 통과라고 하지 말고 미검증으로 남겨줘.
0단계 결과와 다음 단계 진입 가능 여부를 보고하고 종료해줘.
```

## 4 다음 단계를 진행하는 방법

첫 점검이 끝나면 `01-build-steps.md`의 1단계 프롬프트부터 순서대로 전달한다. 각 프롬프트는 해당 단계의 구현·검증·진행 기록 갱신까지 요청한다. 기본 진행 단위는 한 단계다. 다음 단계의 기능을 미리 넓혀 만들지 않도록 한다.

같은 대화에서 이어갈 때는 다음처럼 짧게 요청해도 된다.

```text
handoff/cursor-web-v1.0/02-progress.md의 완료 상태를 확인하고,
01-build-steps.md의 다음 미완료 단계 하나를 구현하고 검증해줘.
앞 단계가 막혀 있으면 그 문제부터 해결해줘.
완료 후 진행 기록과 인수 검증표를 갱신하고 결과를 보고해줘.
```

새 대화를 시작할 때는 다음 프롬프트를 사용한다.

```text
Folduct 웹앱 구현을 이어가줘.
docs/folduct-web-prd-v1.0.md와 handoff/cursor-web-v1.0/의 문서를 읽고,
현재 코드와 진행 기록이 일치하는지 확인해줘.
이미 완료된 기능을 새로 만들지 말고 다음 미완료 단계 하나를 구현·검증해줘.
사용자 변경은 보존하고 미검증 항목은 그대로 표시해줘.
```

## 5 결과를 확인할 때

Cursor의 설명만 보지 말고 단계별 완료 기준에 해당하는 행동을 실제 화면에서 확인한다. `npm run build` 통과는 타입·번들 검증이며 브라우저 권한, 파일 재연결과 데이터 복원까지 검증했다는 뜻은 아니다.

대부분의 개발 명령은 `apps/web`에서 실행한다. 현재 확인된 명령은 `npm run dev`, `npm run build`, `npm run preview`다. 테스트 명령은 1단계에서 실제로 구성한 후 사용한다. 10단계에는 Vercel 배포 준비를 포함한다. 실제 계정 연결·Preview 배포·운영 배포는 별도 실행 요청 후 진행하며 유료 서비스 가입은 임의로 하지 않는다.

## 6 완료 결과

최종 결과는 실행 가능한 웹앱, 저장·복원 검증이 된 핵심 흐름, 실행 안내, 갱신된 진행 기록과 검증표다. 사용자 비교 실험의 성공 수치는 실제 실험 전까지 미검증으로 남긴다. 이 개발 과정에서 완료하는 것은 실험할 수 있는 제품과 측정 준비다.
