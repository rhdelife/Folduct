# Folduct Cursor 단계별 구현 프롬프트

작성일: 2026-10-05 · 대상: Folduct 프로젝트 루트의 apps/web · 사용 방식: 한 번에 한 단계의 프롬프트만 Cursor Agent에 붙여 넣기

이 문서는 WEB PRD와 책상·가방 후속 방향을 실제 개발 대화로 옮기기 위한 작업 지시서다. 제품 요구사항의 기준은 docs/folduct-web-prd-v1.0.md이며, 이 문서는 구현 순서와 매 단계의 검증·보고 방식을 정한다.

## 0. 사용 방법

1. Cursor에서 docs와 apps/web이 함께 보이는 Folduct 프로젝트 루트를 연다.
2. 아래 공통 작업 계약을 읽고 첫 대화에는 준비 단계 프롬프트를 붙여 넣는다.
3. Cursor의 보고에서 실제 완료·미검증·다음 행동을 확인하고 다음 한 단계의 프롬프트만 보낸다. 여러 단계 프롬프트를 한 번에 합치지 않는다.
4. 한 단계가 부분 완료라면 해당 단계의 미완료 사항을 해결한다. 통과하지 않은 인수 기준을 건너뛰지 않는다.
5. docs/02-progress.md의 실제 최신 상태가 이 문서의 출발점보다 우선한다. 2026-10-06 현재 5단계 기능과 선택형 V 시안이 코드에 들어갔다. 5단계의 실제 폴더·브라우저 재실행 등 남은 검증을 먼저 끝내고, 이미 만든 기능을 다시 구현하지 않는다.

### 요구사항 우선순위

1. 사용자의 새 지시와 현재 작업 트리의 실제 변경 상태.
2. docs/folduct-web-prd-v1.0.md의 P0·FR01~14·AC01~27.
3. docs/01-build-steps.md, docs/02-progress.md, docs/03-acceptance.md.
4. docs/folduct-kook-optional-module-draft.md의 B(모바일 가방)·S(기기 간 연결) 후속 방향. 현재 P0 구현을 늘리는 근거로 사용하지 않는다.
5. 같은 문서의 N(Kook 캐릭터·스토리)은 미채택 선택안이다. 사용자의 채택 지시 전에는 제품 UI·데이터·출시 범위에 적용하지 않는다. P(타인에게 공개하는 공유)도 미결정이다.

차별화 기준: Eagle도 수집·검색·미리보기와 영상 타임스탬프 주석을 제공한다. Folduct에서는 중단 전 판단·이유·다음 행동을 재방문 때 복원하고 첫 유효 작업까지 잇는 흐름을 우선한다. 시점 메모나 레트로퓨처리즘을 독립 차별점으로 제시하지 않는다. 핵심 재개 기능은 무료 제공을 목표로 하되 기기 간 자동 동기화의 장기 운영비는 검증 전 보장하지 않는다. 활동·규모 시각화(V)는 현재 선택형 시안이며 효과 검증 전에는 P0 완료 조건으로 간주하지 않는다.

### 공통 작업 계약 — 모든 단계에 적용

- 시작할 때 관련 문서와 현재 코드를 읽고 git 상태를 확인한다. 기존 사용자 변경을 보존하고 임의 초기화·대량 덮어쓰기·이전 단계 재구현을 하지 않는다.
- 한 단계의 사용자 행동을 실제로 끝까지 구현한다. 비어 있는 버튼, 임시 성공 알림, 저장되지 않는 데모 상태를 완료로 표시하지 않는다.
- UI, 도메인, 파일 접근, 저장 계층을 적절히 분리한다. 기존 구조를 확인한 뒤 최소한으로 변경한다. 새 라이브러리는 필요성과 설치 버전을 확인한다.
- 원본은 사용자가 고른 범위에서 읽기 전용으로 다룬다. 원본 쓰기·이동·삭제, 사용자 모르게 파일이나 메모를 원격 전송하기, 외부 편집기 상태 복원 약속을 하지 않는다.
- 샘플과 실제 데이터는 계속 분리한다. 테스트용 파일·브라우저 저장소를 사용하고 실제 사용자 파일을 시험 목적으로 변경하지 않는다.
- 성공 경로와 핵심 실패 경로를 검증한다. 자동 테스트와 실제 브라우저 검증을 구분한다. apps/web에서 제공되는 테스트와 npm run build를 실행한다.
- 관련 docs/02-progress.md와 docs/03-acceptance.md를 실제 결과로 갱신한다. 체크박스는 충족 근거가 있을 때만 바꾼다. 이전 기록은 덮어쓰지 말고 새 기록을 더한다.
- 최종 보고는 실제 동작, 변경 파일, 실행한 검증과 결과, 실패·미검증, 다음 한 단계 순서로 작성한다. 구현과 사용자 실험·배포 완료를 혼동하지 않는다.
- 외부 서비스 선택, 비용, 공개 배포, 원본 데이터 전송, 기존 데이터 마이그레이션 정책 변경이 필요하면 옵션·영향·권장안을 먼저 정리한다. 그 결정과 무관한 작업은 계속한다.

## 1. 준비 단계 — 상태 확인과 한 단계 작업 계획

목적: 오래된 시작 안내 대신 최신 진행 기록을 읽고 바로 다음 한 단계만 착수하게 한다. 이 단계에서는 앱 기능을 변경하지 않는다.

~~~text
Folduct 웹앱의 단계별 작업을 이어갈 거야. 현재 프로젝트 루트를 기준으로 진행해줘.

1. docs/cursor-vibe-implementation-prompts.md의 공통 작업 계약을 읽어줘.
2. docs/folduct-web-prd-v1.0.md, docs/folduct-kook-optional-module-draft.md,
   docs/01-build-steps.md, docs/02-progress.md, docs/03-acceptance.md를 읽어줘.
3. git 상태와 apps/web의 실제 구현을 확인해 진행 기록의 마지막 완료 단계와 코드가 일치하는지 판단해줘.
4. 다음 미완료 단계 하나의 요구사항, 선행 조건, 수정 가능성이 높은 영역,
   성공·실패 검증 시나리오를 짧은 작업 계획으로 정리해줘.
5. 이 점검 단계에서는 앱 기능을 구현하거나 완료 체크를 바꾸지 마.

현재 기록상 3단계까지 완료되어 다음은 4단계 미리보기지만 최신 코드와 기록이 다르면 실제 상태를 우선해줘.
Kook 스토리(N)는 미채택이고 모바일 가방(B)·기기 간 연결(S)은 P0 이후의 후속 방향이야.
마지막에 다음으로 붙여 넣을 이 문서의 정확한 단계 제목을 알려줘.
~~~

## 2. 핵심 제품 완성 — 기존 P0 단계

### 2-1. 미리보기와 보기 상태 — 기존 4단계

진입 조건: 3단계 작업면·저장 상태 확인. 관련: PRD FR06, AC08~09, 기존 지시서 4단계.

완료 장면: 카드에서 파일을 고르면 실제 미리보기가 열리고 미지원·손상 파일은 해당 카드에만 제한 안내가 보인다. 영상·음원의 마지막 위치를 저장해 다음 방문에 복원하되 소리는 자동으로 시작하지 않는다.

~~~text
Folduct의 기존 4단계만 구현해줘. 먼저 docs/cursor-vibe-implementation-prompts.md의 공통 작업 계약과
PRD FR06, docs/01-build-steps.md 4단계, 최신 진행 기록을 확인해줘.

구현 범위:
- 선택 카드와 실제 연결 파일을 잇고 PNG/JPEG/WebP, UTF-8 일반 텍스트의 미리보기를 제공해줘.
- 브라우저가 지원하는 영상·음원은 명시적인 재생 동작으로만 시작하고 PDF는 브라우저 보기와 별도 열기를 제공해줘.
- Markdown·코드·HTML·SVG는 P0에서 안전한 일반 텍스트로 보여줘. 스크립트나 삽입 콘텐츠가 실행되면 안 돼.
- Office·한글·디자인 파일, 손상 파일, 코덱 미지원, 크기 초과, 읽기 실패의 안내를 구분해줘.
- 미디어 위치를 작업면에 저장하고 재방문 시 재생 길이 안으로 보정해줘. PDF 페이지 위치 복원은 추가하지 마.
- 카드를 빠르게 바꿀 때 이전 비동기 결과가 새 카드에 나타나지 않게 하고 object URL을 적절한 시점에 해제해줘.
- 폴더 권한을 잃어도 기존 카드·메모는 읽을 수 있게 해줘. 권한 복구 전체 흐름은 6단계에서 한다.

AC08~09, 짧아진 영상의 위치 보정, 연속 선택, 크기 제한, 악성 HTML·SVG 비실행,
미지원 파일 하나가 전체 앱을 멈추지 않는 경우를 검증해줘.
테스트와 빌드를 실행하고 실제 폴더·브라우저에서 확인하지 못한 것은 미검증으로 기록해줘.
이번에는 Kook 연출, 모바일 가방, 계정·동기화, 5단계 장면 기능을 만들지 마.
진행 기록·검증표를 갱신한 뒤 실제 완료와 5단계 진입 가능 여부를 보고해줘.
~~~

### 2-2. 여기서 멈추기와 장면 이어가기 — 기존 5단계

진입 조건: 미리보기와 저장할 보기 상태가 안정적이다. 관련: PRD S03~05, FR08~09, AC10~14.

~~~text
Folduct의 기존 5단계만 구현해줘. 공통 작업 계약, PRD S03~05·FR08~09,
기존 지시서 5단계와 최신 진행·검증 기록을 먼저 확인해줘.

완성할 사용자 여정:
1. 사용자가 작업면에서 '여기서 멈추기'를 누른다.
2. 선택적인 다음 행동(200자)과 장면 이름(60자)을 입력하거나 비운 채 저장한다.
3. 미확정 편집을 반영한 현재 작업, 불변 장면, 마지막 중단 장면 참조가 원자적으로 저장된다.
4. 저장이 성공했을 때만 책상으로 돌아간다.
5. 다시 열면 최근 현재 작업의 카드·메모·선택·보기 상태와 다음 행동이 보인다.
6. 과거 장면은 읽기 전용이고, '이 장면에서 이어가기'는 직전 현재 작업을 안전 장면으로 남긴 뒤 사본을 적용한다.

필수 실패 처리:
- 연속 클릭·중복 요청으로 장면을 두 번 만들지 마. 실패 시 대화상자 입력과 현재 화면을 유지해줘.
- 안전 장면 공간 부족 또는 트랜잭션 실패 시 현재 작업을 교체하지 마.
- 장면 생성 이후 카드 편집이 과거 장면을 바꾸지 않도록 깊은 복사와 참조 규칙을 확인해줘.
- 마지막 중단 장면 이후 자동 저장 변경이 있으면 최신 현재 작업을 우선하고 그 사실을 알려줘.
- 책상의 '이어서 시작'에서 최근 작업면을 열 때 마지막 선택 카드, 그 이유 메모, 다음 행동,
  파일 접근·변경 상태를 한곳에 모은 재개 요약을 보여줘. 카드로 바로 이동하거나 요약을 닫고 작업면을 볼 수 있게 해줘.
  이유가 없으면 추측해 채우지 말고 기존 데이터만 사용해줘. 새 필수 입력을 만들지 마.
- 과거 장면을 원본 파일의 과거 버전처럼 설명하지 마.

AC10~14를 성공·실패 경로로 검증해줘. 특히 연속 클릭, 저장 직전 편집,
장면 한도, 읽기 전용 열람 취소, 안전 장면 실패 전체 롤백을 확인해줘.
테스트·빌드·진행 기록·검증표를 갱신하고 6단계로 갈 수 있는지 보고해줘.
Kook이나 모바일 기능은 이번 단계에 넣지 마.
~~~

### 2-3. 권한·파일 변경·재연결 — 기존 6단계

진입 조건: 현재 작업과 과거 장면을 구분해 열람할 수 있다. 관련: PRD FR10~12, AC15~19·27.

~~~text
Folduct의 기존 6단계만 구현해줘. 공통 작업 계약, PRD FR10~12,
기존 지시서 6단계와 최신 진행·검증 기록을 먼저 읽어줘.

- 재방문 때 폴더 접근이 끊겨도 책상·작업면·장면의 배치와 메모부터 보여줘.
- 사용자가 직접 누를 때만 폴더 권한을 다시 요청하거나 폴더를 재선택하게 해줘.
- 디렉터리 입력 폴백에서는 폴더 이름만 믿지 말고 경로 일치·누락·신규 항목 수를 보여준 뒤 확인받아줘.
- 완전한 스캔에서만 누락을 확정하고 취소·권한 실패·한도 초과에서는 unknown을 유지해줘.
- 원본 변경은 동일 Asset ID를 유지하면서 장면 당시 메타데이터와 현재 값을 비교해 표시해줘.
- 파일이 이동·삭제되어도 카드와 이유 메모는 유지하고 사용자 확인을 거친 경로 재연결을 제공해줘.
- 같은 Asset을 쓰는 다른 카드와 과거 장면에 연결 변경이 미치는 영향을 사전에 알려줘.
- 다른 Asset의 기존 경로와 충돌하면 참조·메모를 손실하지 않는 일관된 규칙으로 처리해줘.

테스트 전용 폴더로 변경·이동·삭제, 불완전 스캔, 같은 이름의 다른 루트,
공유 Asset 재연결을 검증해줘. 실제 사용자 원본 파일을 시험 목적으로 수정하지 마.
AC15~19·27과 브라우저별 미검증 상태를 기록하고 테스트·빌드를 실행해줘.
모바일 가방이나 동기화로 폴더 권한 문제를 우회하지 마.
~~~

### 2-4. 백업과 저장소 복구 — 기존 7단계

진입 조건: 파일 참조와 재연결 규칙이 확정되어 있다. 관련: PRD FR13~14, AC20~21·26.

~~~text
Folduct의 기존 7단계만 진행해줘. 공통 작업 계약, PRD FR13~14,
기존 지시서 7단계와 진행 기록의 백업 용량 쟁점을 먼저 읽어줘.

먼저 최대 지원 데이터로 .folduct.json의 실제 크기를 측정해줘. 현재 10MiB 가져오기 상한과
정상 내보내기 크기가 충돌하면 임의로 기록을 지우거나 줄이지 마.
~~~

~~~text
사용자가 확정한 docs/device-sync-decision-draft.md의 S1 범위만 구현해줘.
공통 작업 계약과 결정 기록을 읽고 승인되지 않은 서비스·데이터 범위를 넓히지 마.

미동의 항목, 폴더 핸들, 데스크톱 원본 전체, 로컬 파일 경로가 전송되지 않도록 검사해줘.
재시도·중복 요청·연결 해제·로그아웃에서 기존 로컬 기록이 조용히 사라지지 않게 해줘.

자동 테스트·빌드·네트워크 요청 검사를 실행해줘. 미검증은 그대로 표시해줘.
~~~

### 3-6. S2 — 충돌·삭제·복구와 동기화 인수 검증

진입 조건: S1의 기본 전송이 동작한다.

~~~text
승인된 S 정책의 충돌·삭제·복구만 마감해줘. 공통 작업 계약과 S0 결정 문서,

두 기기에서 같은 메모 수정, 오프라인 수집 후 재접속, 중복 항목 업로드,
한 기기에서 삭제와 다른 기기에서 수정이 겹치는 경우를 재현해줘.
사용자가 어느 버전을 유지할지 알아야 하는 충돌은 조용히 덮어쓰지 마.
계정 해지·기기 연결 해제·서버 오류에서 로컬과 원격 사본의 처리 결과를 명확히 표시해줘.
원본 폴더·핸들과 선택하지 않은 항목이 전송되지 않는지 다시 확인해줘.

S 전용 인수 기준을 실제 두 기기 흐름과 실패 테스트로 검증하고
PRD의 기존 로컬 저장·백업·장면 흐름을 회귀 확인해줘.
테스트·빌드·진행 기록·사용자 안내를 갱신해줘.
외부 공개(P)는 별도 제품 결정 전까지 만들지 마.
~~~

## 4. Kook 스토리 — 선택안으로만 다루는 단계

N은 B·S와 독립적이다. 현재 결정은 미채택이다. N0는 구현 승인 없이도 디자인 검토 자료로 만들 수 있다. N1은 사용자가 Kook 스토리 채택을 명시한 뒤에만 실행한다.

### 4-1. N0 — 이야기·시각 언어 시안, 앱 코드 변경 없음

~~~text
Kook 스토리 선택안(N)의 검토 자료를 만들어줘. 아직 제품에 적용하지 마.
공통 작업 계약, folduct-kook-optional-module-draft.md의 N 항목,
현재 책상·작업면 화면과 실제 데이터 우선순위를 확인해줘.

docs/kook-story-prototype-draft.md에 다음을 정리해줘:
- Kook의 역할과 성격, '발견 → 펼치기 → 떠나기 → 돌아오기'의 짧은 장면 구성.
- 빈 책상, 작업 중, 중단, 재방문에서의 한 문장 카피와 오브제 표현.
- 레트로퓨처리즘의 색·재질·타이포·움직임·소리 원칙과 과용하지 않을 기준.
- 캐릭터를 끈 중립 UI에서도 동일한 정보·행동을 제공하는 대응안.
- 저장 실패·권한 거부·파일 누락처럼 정확한 안내가 필요한 예외.
- 샘플 Kook 자료와 사용자의 실제 자료가 섞이지 않는 방법.
- 기존 화면과 시안의 비교·검증 질문, 채택 판단 기준.

영화 속 인물의 얼굴·의상·장면·대사를 복제하지 마.
앱 코드·P0 인수 기준·출시 범위를 바꾸지 말고 사용자 검토용 초안만 작성해줘.
~~~

### 4-2. N1 — 명시적 채택 후 탈부착 가능한 표현 구현

진입 조건: 사용자가 Kook 스토리 채택과 적용 화면을 명시했다. 미채택 상태에서는 실행하지 않는다.

~~~text
사용자가 채택한 Kook 표현 범위만 구현해줘. 공통 작업 계약,
승인된 kook-story-prototype-draft.md와 N-AC01~04를 읽어줘.

표현을 기존 핵심 UI 위의 분리 가능한 층으로 만들어줘.
설정에서 Kook 표현을 끄면 프로젝트·카드·장면·메모·다음 행동·URL·백업이 그대로 유지되고
중립 카피와 기본 오브제로 동일한 행동을 할 수 있어야 해.

샘플 Kook 자료는 실제 프로젝트와 분리하고 효과 때문에 저장 상태·파일명·다음 행동이 가려지지 않게 해줘.
동작 줄이기·소리 끄기·키보드·200% 확대·목록 보기에서 같은 핵심 흐름을 제공해줘.
저장 실패·권한 상실·파일 누락은 직접적이고 정확한 문구로 표시해줘.

N-AC01~04와 기존 AC01~27의 핵심 회귀 시나리오를 검증해줘.
~~~

## 5. Cursor가 매번 제출할 결과 형식

Cursor의 매 단계 마지막 답변은 다음 내용을 실제 실행 결과로 채운다. 빈 항목을 추측해 채우지 않는다.

~~~text
완료 단계:
이번에 사용자가 실제로 할 수 있게 된 행동:
변경한 파일과 이유:
실행한 테스트·빌드·브라우저 확인 및 결과:
통과한 인수 기준과 근거:
실패·미검증 항목과 재현 방법:
기존 사용자 데이터와 원본 파일에 대한 영향:
다음에 붙여 넣을 프롬프트 제목:
~~~

현재 P0 작업은 준비 단계에서 실제 코드를 확인한 뒤 **5단계 남은 검증**부터 시작한다. 그 결과를 기록한 다음 2-3(6단계) → 2-4(7단계) → 2-5(8단계) → 2-6(9단계)로 진행한다. 2-1·2-2는 이미 구현된 기능의 누락이 발견될 때만 참고한다. 모바일 가방과 동기화는 그 뒤 별도 범위로 진행한다. Kook은 N0 검토 후 채택할 때만 N1으로 넘어간다.

## 6. V 모듈 — 시각적 데이터 표현 검토안

V는 Kook 스토리와 독립적이다. 2026-10-06 현재 웹에는 선택형 ‘작업한 날’·‘자료 수’ 시안과 로컬 날짜 집계가 구현되었다. 이 구현이 사용자 효과를 입증하거나 최종 시각 문법을 확정한 것은 아니다. 기존 데스크톱 colorMemoryFor는 마지막 열람 뒤 지난 시간으로 채도를 줄이는 코드이므로 사용 빈도 측정으로 간주하지 않는다. V0는 **기존 시안의 검토**로 수행하고, V1은 사용자가 개선 범위를 채택한 후에만 실행한다.

### 6-1. V0 — 채도·자료 규모 시각화 설계 검토

~~~text
Folduct의 현재 V 시안을 검토하되 앱 코드는 바꾸지 마.
공통 작업 계약, folduct-kook-optional-module-draft.md의 V 항목,
현재 Project·RootRecord·Asset 모델과 기존 데스크톱 colorMemoryFor를 확인해줘.

먼저 네 가지를 구분해줘: 최근 30일 실제 작업한 날짜 수, 마지막 작업 뒤 지난 시간,
완전한 폴더 스캔에서 확인한 파일 수, 확인된 파일의 총 바이트. 현재 데이터만으로 알 수 없는 값은 '알 수 없음'으로 표시해줘.

docs/visual-encoding-prototype-draft.md에 다음을 작성해줘:
- 어떤 행동을 작업 날짜로 셀지, 호버·단순 열람을 왜 제외하는지.
- 활동 표현은 표지 원본 색을 보존하고 작은 장식 띠만 조절하는 시안.
- 자료 수 표현은 기존 카드 위치·클릭 영역을 고정하고 종이 묶음 두께 같은 내부 요소만 달리하는 시안.
- 파일 수에 따른 종이 묶음과 총 바이트에 따른 용량 표현을 따로 비교하고, 어느 쪽이 사용자 과제에 유용한지 판단할 근거.
- 부분 스캔·오래된 스캔·새 프로젝트의 '미확인' 표현과 기존 제외 파일 범위.
- 기본 보기 / 작업 빈도 보기 / 자료 수 보기, 범례·정확한 숫자·목록 보기.
- 단계 구간을 프로젝트마다 자동으로 바꾸지 않는 일관된 기준. 용량 보기는 검증 후 별도 후보로 취급.
- 저활동 프로젝트가 저중요 프로젝트로 오해되지 않는지 확인할 사용자 과제.
- 키보드, 색각 차이, 비텍스트 대비, 동작 줄이기, 12개 프로젝트의 겹침 위험.
- 기존 데스크톱의 1년 뒤 거의 흑백이 되는 공식을 그대로 쓰지 않을 이유.

현재 시안과 샘플 데이터로 표현안을 검토하고 실제 사용자 효과나 작업 빈도를 지어내지 마.
V를 채택하지 않아도 기존 데이터·화면이 온전히 동작하는 구조를 권장해줘.
~~~

### 6-2. V1 — 명시적 채택 후 제한된 구현

진입 조건: 사용자가 V의 데이터 정의·표현 범위·기준 구간을 명시적으로 채택했다.

~~~text
승인된 visual-encoding-prototype-draft.md의 V1 범위만 구현해줘.
공통 작업 계약과 V-01~03, 실제 Project·RootRecord·Asset 저장 구조를 읽어줘.

실제 작업한 날짜의 로컬 집계가 필요하다면 최소 저장 구조와 마이그레이션을 설계하고
기존 데이터는 추정하지 말고 '기록 없음'으로 남겨줘. 호버나 단순 열람을 활동으로 세지 마.
자료 수는 완전한 스캔의 확인값만 사용하고 불완전·오래된 스캔에는 기준 시각과 제한을 표시해줘.
승인 범위에 용량 보기가 포함됐다면 확인된 파일 바이트의 합계로만 계산하고 파일 수와 같은 시각 규칙으로 혼용하지 마.
프로젝트 표지 이미지, 사용자 지정 위치, 카드 크기, 클릭 영역을 바꾸지 마.
장식의 채도와 내부 두께는 범례·정확한 텍스트 값·목록 보기로도 읽히게 해줘.
시각화 끄기, 키보드·동작 줄이기, 200% 확대를 지원해줘.

활동이 적은 중요한 프로젝트, 파일 한 개가 매우 큰 프로젝트, 파일은 많지만 저장 용량은 작은 프로젝트,
부분 스캔, 새 프로젝트를 검증해줘. 저장·백업·장면의 기존 흐름도 회귀 확인해줘.
사용자 과제에서 값의 의미를 잘못 읽거나 재개가 느려지면 V를 완료로 표시하지 말고 결과를 보고해줘.
~~~

V0는 P0 완료 후 N·B·S와 독립적으로 검토할 수 있다. V1은 데이터 뜻과 표현 기준을 사용자가 채택한 경우에만 진행한다. 작업 빈도와 자료 수를 실제보다 많이 아는 것처럼 표현하지 않는다.
