# Folduct WEB PRD 후속 방향 — 책상·가방과 Kook 선택 스토리

상태: **책상·가방 연결은 후속 방향 / Kook 스토리는 미채택 선택안** · 작성일: 2026년 10월 5일 · 기준: [Folduct WEB PRD 1.0](./folduct-web-prd-v1.0.md)

## 1. 적용 규칙과 결정 경계

이 문서는 Folduct의 기존 ‘폴더 연결 → 배치와 이유 메모 → 중단 기록 → 재방문·이어가기’에 모바일 가방과 기기 간 연결을 더할 후속 방향을 기록한다. Kook 캐릭터와 스토리 연출은 별도의 선택안이다. 현재 출시 지시서가 아니며 기존 PRD의 P0·P1, FR01~14, AC01~27을 대체하거나 완료 조건을 늘리지 않는다. 후속 출시 범위가 확정되기 전에는 개발·시연·검증에서 필수 항목으로 취급하지 않는다.

Eagle 같은 자산 관리 도구도 수집·분류·검색·주석을 제공한다. 가방의 존재 이유는 더 많은 자료를 모으는 것이 아니라 **이동 중 생긴 생각을 책상에서 다음 작업 결정으로 이어주는 것**이다. 가방 항목이 프로젝트의 판단·다음 행동에 연결되지 않는다면 수집 형식을 늘리지 않는다. Kook의 외형과 공간 연출도 기능적 차별점으로 주장하지 않는다.

선택 단위는 다음처럼 분리한다.

| 모듈 | 내용 | 의존 관계 | 현재 결정 |
| --- | --- | --- | --- |
| N — Kook 이야기·시각 언어 | 캐릭터의 흔적, 레트로퓨처리즘, 책상 표현 | 기존 웹 핵심 흐름 | 미채택 선택안 |
| V — 시각적 데이터 표현 | 작업한 날과 자료 수를 오브제 장식에 표현 | 실제 측정값·접근성 검증 필요; N과 독립 | 선택형 코드 시안, 효과 미검증 |
| B — 모바일 가방 | 이동 중 빠른 수집과 확인 | N 없이 구현 가능; 기기 간 연결은 S 필요 | 후속 방향, 상세 범위 미정 |
| S — 기기 간 연결 | 가방과 책상 사이 선택 데이터 동기화 | 계정·원격 저장·동의·충돌 정책 필요 | 후속 방향, 상세 범위 미정 |
| P — 외부 공유 | 다른 사람에게 선택 자료·장면 공개 | 별도 권한·공개 범위·삭제 정책 필요 | 미결정 |

N의 채택 여부는 B·S에 영향을 주지 않는다. B의 같은 기기 데모를 만들더라도 다른 기기와 연결된다고 안내하지 않는다. 여기서 책상과 가방의 ‘공유’는 우선 **내 기기 사이 동기화(S)**로 정의한다. **다른 사람에게 공개(P)**할지는 별도 결정한다.

N을 제거할 때는 캐릭터·스토리 문구·표현 자산과 관련 설정만 제외한다. B·S의 데이터 흐름과 화면 역할은 유지한다. 프로젝트·카드·장면의 식별자와 저장 형식, 기존 URL, 백업 파일은 그대로 해석할 수 있어야 한다. 캐릭터 표시 여부 때문에 기록의 내용이나 접근 권한이 달라져서는 안 된다.

V도 N 없이 적용하거나 제거할 수 있어야 한다. V를 꺼도 표지·위치·선택 상태와 프로젝트 기록이 그대로 유지된다. 데이터 표현 설정은 프로젝트 자체의 중요도나 사용자의 판단을 대체하지 않는다.

## 2. 제품 가설과 스토리라인

**경험 가설:** 사용자가 중단한 작업을 ‘책상에 남은 흔적’으로 보고, 이동 중 떠오른 생각을 ‘가방에 넣은 단서’로 다루면, 자료의 역할과 다음 행동을 더 쉽게 기억할 수 있다. **N의 추가 가설:** 어질러진 책상과 Kook의 이야기가 이 경험의 이해와 재방문 동기를 높일 수 있다. 감정적 몰입만으로 성공을 판단하지 않는다. 핵심 기준은 작업 재개 시간, 기록에 든 수고, 재방문 성공이다.

N을 채택할 경우 Kook은 미완성 작업과 발견한 단서를 가지고 다니는 창작자다. 완벽하게 정리된 미래보다 따뜻한 아날로그 물건과 조용한 미래 기기가 공존하는 세계에 산다. Kook의 성격은 호기심, 약간의 서투름, 다시 돌아와 끝내려는 태도로 표현한다. 영화 속 특정 인물은 분위기 참고에 그치며 얼굴·의상·장면·대사를 재현하지 않는다.

사용자가 겪는 네 장면은 다음과 같다.

1. **발견:** 밖에서 본 이미지, 들은 소리, 떠오른 문장을 가방에 담는다. 수집 순간에는 분류를 강요하지 않는다.
2. **펼치기:** 책상에서 자료를 꺼내 프로젝트 안에 놓고, 필요한 경우 선택 이유를 적는다.
3. **떠나기:** 작업을 멈추며 다음 행동을 한 줄 남긴다. 책상 배치와 장면이 보존된다.
4. **돌아오기:** 마지막으로 보던 자료, 이유, 다음 행동을 함께 확인하고 이어간다.

N을 채택하더라도 Kook은 사용자의 프로젝트 내용을 대신 쓰거나 판단하는 인물이 아니다. 첫 체험의 샘플 프로젝트, 빈 상태, 중단·재방문 전환에서 공간의 주인 또는 안내자로 나타날 수 있다. 실제 사용자의 책상에서는 데이터와 행동이 주인공이어야 한다. 사용자 자료와 Kook의 허구 자료는 분명히 구분한다.

## 3. N 모듈 — 웹 책상의 이야기와 UI

### N-01 화면 역할

기존 S01 개인 책상은 프로젝트를 고르고 다시 들어가는 자리, S02 작업면은 자료를 펼쳐 판단하는 자리로 유지한다. Kook 표현은 화면 구조를 바꾸기보다 프로젝트 오브제, 빈 상태, 장면 전환, 상태 안내에 입힌다. ‘책상’은 비주얼 테마만이 아니라 위치와 겹침을 통해 사용자가 만든 관계를 기억하는 인터페이스다.

처음 보는 샘플 책상에는 Kook의 사진·티켓·카세트·메모 같은 허구 자료를 둘 수 있다. 샘플임을 명확히 표시하고 실제 프로젝트를 연결할 때 별도 저장 공간을 사용한다. 실사용 책상에서는 프로젝트 이름, 연결 상태, 저장 상태, 다음 행동과 ‘이어서 시작’이 장식보다 먼저 읽혀야 한다.

### N-02 시각·동작 원칙

- 레트로퓨처리즘은 따뜻한 종이·직물·낡은 플라스틱 질감에 절제된 디스플레이 빛과 기계적 디테일을 결합한다. 특정 시대의 기기 화면을 그대로 복제하지 않는다.
- ‘어질러짐’은 초기 배치와 오브제의 겹침으로 느끼게 하되, 실제 카드 좌표는 사용자의 선택을 우선한다. 효과를 켜거나 화면 크기를 바꿔도 저장 좌표를 임의로 재정렬하지 않는다.
- 상태는 문장과 아이콘으로 명확히 표시한다. 먼지·채도·흔들림만으로 오래됨, 누락, 저장 실패를 표현하지 않는다.
- 캐릭터의 움직임·사운드·전환은 자동 재생을 기본으로 하지 않는다. 동작 줄이기와 소리 끄기를 제공하고, 키보드와 목록 보기에서 같은 핵심 행동을 수행할 수 있어야 한다.
- Kook의 말투는 짧고 드물게 사용한다. 파일 접근 거부·저장 실패·복구 여부처럼 정확성이 중요한 안내는 기존의 직접적인 문구를 사용한다.

### N-03 전환 지점

| 순간 | 허용하는 이야기 표현 | 항상 보이는 실용 정보 |
| --- | --- | --- |
| 빈 책상 | Kook의 샘플 물건과 한 문장 안내 | 샘플 체험, 내 폴더 연결 |
| 작업 중 | 물건의 재질·그림자·라벨 | 자료명, 선택 이유, 저장 상태 |
| 여기서 멈추기 | 책상을 떠나는 짧은 전환 | 다음 행동 입력, 저장 성공/실패 |
| 재방문 | 마지막 위치로 돌아오는 짧은 전환 | 마지막 자료, 이유, 다음 행동, 권한 상태 |

N은 설정에서 끌 수 있는 표현 계층으로 설계한다. 꺼도 정보·기능·저장된 배치가 유지되고, 같은 내용을 중립적인 문구와 기본 오브제로 읽을 수 있어야 한다. 다만 이 설정의 UI 구현도 N 채택 후 범위에 포함한다.

## 4. V 모듈 — 활동과 자료 규모의 시각적 표현 검토안

> 2026년 10월 18일: V 모듈은 [PRD 2.0](./folduct-prd-v2.0.md) FR15~19(방치 판정·물건 크기·방 용량)로 대체되었다. ‘크기’는 저장 용량으로 확정했다. 아래는 결정 기록으로 남긴다.

2026-10-06 현재 웹에는 선택형 ‘작업한 날’·‘자료 수’ 보기와 로컬 날짜 집계가 시안으로 구현되었다. 이 구현은 기준 구간·이해도·재개 속도 검증을 대신하지 않는다. Kook과 무관하게 끌 수 있으며 핵심 P0 흐름을 막는 출시 조건으로 삼지 않는다.

### V-01 데이터의 뜻을 먼저 분리한다

- **작업 빈도:** 최근 30일 중 해당 프로젝트에서 카드 배치·메모 편집·장면 저장 같은 실제 작업 행동이 있었던 날짜 수. 한 날짜는 여러 번 작업해도 한 번으로 센다. 마우스 호버, 책상 지나가기, 프로젝트를 잠깐 열어본 행동, 자동 새로고침은 세지 않는다. 따라서 UI에도 ‘사용 빈도’보다 ‘최근 30일 작업한 날’이라고 정확히 적는다. 열람만 하는 사용은 별도 관찰한 뒤 포함 여부를 결정한다. 활동 기록은 해당 기기의 로컬 집계로 시작한다. 다른 기기와 합친 빈도로 표시하려면 S의 명시적 동기화 범위를 따로 결정한다.
- **최근 작업 시각:** 마지막 활동 이후 지난 시간이다. 활동 빈도와 다른 값이므로 ‘최근 작업: 5일 전’처럼 텍스트로 표시한다. 기존 데스크톱의 `colorMemoryFor(lastSeenAt)`은 이 경과 시간으로 채도를 낮추는 구현이며 사용 빈도를 측정하지 않는다. 14일 이후부터 변색해 1년에는 채도 8%까지 낮추는 규칙을 웹에 그대로 이식하지 않는다.
- **자료 규모:** ‘파일 수’와 ‘저장 용량(파일별 바이트 합계)’은 다른 값이다. 종이 묶음의 두께 시안은 먼저 **완료된 폴더 스캔에서 확인한 파일 수**로 시험한다. 사용자가 원하는 ‘크기’가 실제 저장 용량이라면 같은 오브제에 뜻을 바꿔 끼우지 말고 용량 전용 시안을 별도로 비교해 채택 여부를 정한다. 용량을 합산할 때에도 확인된 파일의 메타데이터만 사용하며 원본을 읽거나 업로드하지 않는다. 숨김 파일·폴더, `.git`, `node_modules` 등 기존 스캔 제외 범위와 확인 시각을 설명한다. 부분 스캔·권한 상실·1,000개 한도에서는 폴더 전체의 정확한 파일 수나 용량을 안다고 표시하지 않는다.

활동 빈도가 낮거나 자료 수가 적다는 이유로 중요도가 낮다고 해석하지 않는다. 사용자가 고정한 프로젝트와 다음 행동은 시각 효과와 관계없이 동일하게 찾을 수 있어야 한다.

### V-02 권장 시각 문법

기본 책상에서는 표지 이미지·텍스트·카드 테두리의 식별성을 유지한다. 활동 빈도는 오브제의 **작은 장식 띠나 빛의 강도**에만 절제된 채도 차이로 보여준다. 최근 활동이 적은 프로젝트를 거의 흑백으로 만들지 않는다. ‘활동이 많다’는 뜻을 텍스트·아이콘·범례로 함께 전달하고, 데이터가 없거나 새 프로젝트면 낮은 활동과 구분한다.

자료 수는 전체 오브제의 클릭 영역이나 사용자가 정한 위치를 바꾸기보다 **종이 묶음의 두께, 파일 탭의 층수, 옆면 패턴**처럼 내부 요소로 세 단계 정도 표현한다. 실제 파일 수를 함께 적고 단계 구간은 샘플 데이터 분포와 이해도 시험 뒤 확정한다. 영상 한 개가 수 GB여도 이 표현에서는 파일 한 개다. 저장 용량이 더 유용한 과제라면 별도 용량 보기에서 ‘확인된 파일 합계: 3.2GB’처럼 단위를 붙인 값과 별도 시각 문법을 시험한다. 부분 스캔은 확정된 규모 단계 대신 ‘현재까지 최소 n개 확인’ 안내를 쓴다. 한 프로젝트에 큰 파일 한 개가 추가되어도 전체 책상 배치가 갑자기 변하면 안 된다.

동시에 여러 변수를 강하게 띄우지 않는다. 기본 보기와 ‘작업 빈도 보기’·‘자료 수 보기’처럼 사용자가 하나씩 살펴보는 방식을 우선 시험한다. 용량 보기는 별도 시안 검증 뒤에만 후보로 더한다. 호버·키보드 초점·터치 상세에서 정확한 값과 기준 기간, 마지막 확인 시각을 보여준다. 호버나 단순 열람만으로 작업 빈도를 다시 계산하지 않는다. 목록 보기에도 같은 숫자와 상태가 있어야 한다. 단계 구간은 프로젝트마다 자동 정규화하지 말고 동일한 기준을 유지해 색과 두께의 뜻이 책상 전체에서 일관되게 읽히도록 한다.

### V-03 구현 경계와 검증

V는 기존 12개 프로젝트 책상 배치, 사용자가 정한 위치·표지, 카드 크기, 논리 좌표와 독립적이어야 한다. 활동 날짜 집계에는 현재 프로젝트의 `updatedAt`이나 마지막 중단 시각만으로는 부족하다. 현재 시안은 같은 브라우저의 IndexedDB `settings`에 프로젝트별 작업 날짜만 집계하고 기존 데이터는 ‘기록 없음’으로 취급한다. 과거 활동을 추측해 채우지 않는다. 이 시안의 날짜 집계는 장면·백업 파일에 포함하지 않으며 향후 프로젝트 삭제 기능에서는 함께 제거해야 한다. 다른 기기에서 가져온 기록과 합산된 ‘전역 빈도’처럼 표시하지 않는다. 자료 수는 완전한 스캔의 결과만 사용하며 오래된 스캔값에는 확인 시각을 함께 보여준다.

색 하나만으로 상태를 전달하지 않고 텍스트·형태를 함께 제공한다. 필요한 그래픽과 조작 요소의 대비를 확인하고 동작 줄이기를 따른다. [WCAG 2.2 색 사용](https://www.w3.org/TR/WCAG22/#use-of-color), [비텍스트 대비](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html), [움직임 줄이기 기법](https://www.w3.org/WAI/WCAG22/Techniques/css/C39)을 검증 기준으로 사용한다.

V-AC 초안: 사용자가 범례 없이도 ‘작업 빈도’와 ‘자료 수’를 서로 바꾸어 읽지 않고, 텍스트·목록 보기에서도 정확한 값을 찾는다. 작업 빈도가 낮아도 프로젝트 제목·표지·다음 행동을 동일하게 찾을 수 있다. 스캔이 불완전하면 확정값으로 오해하지 않는다. 용량 시안을 시험한다면 파일 수와 바이트를 구별하는지도 확인한다. V를 끄거나 책상을 축소해도 저장 좌표가 바뀌지 않는다. 동일한 중단·재개 과제를 기본 UI와 V UI에서 비교해 탐색 속도와 오해 사례를 기록한다. 결과가 좋지 않으면 V를 채택하지 않는다.

## 5. B 모듈 — 모바일 가방

### B-01 정보 구조와 기본 행동

모바일 가방은 작은 책상 편집기가 아니라 **빠른 수집함과 재방문 안내**다. 사용자는 사진, 짧은 음성, 텍스트, 링크 중 채택한 형식을 가방에 넣고 임시 제목·메모를 덧붙일 수 있다. 프로젝트를 즉시 고르지 않아도 ‘미분류’ 칸에 남는다. 가방에서는 오늘 담은 것, 프로젝트별 주머니, 다음 행동을 볼 수 있다.

수집 성공 건수보다 **책상에서 다시 꺼내 실제 판단이나 다음 행동에 사용한 항목 비율**을 먼저 확인한다. 수집 시간이 기록·재개 시간을 늘리면 형식과 입력 단계를 줄인다. 브라우저 확장, 대량 가져오기, 자동 태그와 범용 자료 라이브러리는 이 모듈의 초기 목표가 아니다.

웹 책상에는 가방에서 온 항목을 ‘아직 놓지 않은 물건’으로 보여준다. 사용자가 프로젝트와 카드 위치를 확정하면 작업면에 놓인다. 자동 배치는 기존 카드·영역을 밀거나 원본 폴더 구조를 바꾸지 않는다. 중복 항목은 식별하고, 삭제·이동·실패 시 가방과 책상 중 어느 상태가 바뀌는지 보여준다.

### B-02 출시 전 제한

기존 PRD의 모바일 범위는 데모와 지원 안내뿐이다. B·S 출시 범위가 확정되기 전에는 모바일 수집·편집·기기 간 복원을 구현 완료로 표시하지 않는다. B를 S 없이 독립 시험할 경우 같은 브라우저의 로컬 데모로만 설명하고, 저장 데이터가 다른 기기에 나타난다는 표현을 사용하지 않는다.

모바일 기기에서 데스크톱의 로컬 폴더 핸들을 그대로 사용할 수 있다고 가정하지 않는다. 가방에 담은 사진·녹음과 책상의 로컬 파일 참조는 서로 다른 출처로 표시해야 한다.

## 6. S·P 모듈 — 연결과 공유의 별도 결정

### S-01 내 기기 사이 연결을 구현할 경우

기기 간 연결에는 계정 식별, 인증, 원격 저장, 네트워크 실패와 충돌 처리, 데이터 삭제·내보내기 정책을 새 PRD로 확정해야 한다. 첫 동기화 후보는 모바일에서 의도적으로 담은 텍스트·링크·선택한 축소 미리보기와 프로젝트 연결 정보다. 데스크톱 원본 폴더 전체, 폴더 핸들, 파일 경로, 전체 파일 내용은 기본 동기화 대상이 아니다.

동기화 시작 전 어떤 자료가 기기 밖으로 전송되는지 항목별로 표시하고 사용자가 선택한다. 오프라인 수집 후 재연결, 중복 업로드, 두 기기에서 같은 메모 수정, 계정 해지 시 로컬 사본 처리, 백업과 원격 데이터의 관계를 정해야 한다. 현재의 `.folduct.json` 백업이 자동 동기화나 원본 파일 백업으로 오인되지 않게 한다.

### P-01 다른 사람에게 공개를 채택할 경우

공개는 S와 별도 기능이다. 사용자가 고른 장면·설명·허용한 미리보기만 공유 후보가 될 수 있다. 공개 전 미리보기, 접근 범위, 링크 취소·삭제, 원본 파일과 개인 메모의 제외 규칙을 정의한다. 협업 편집을 뜻하지 않으며 초기 웹 PRD의 출시 범위에 포함하지 않는다.

## 7. 검증 기준과 채택 판단

N을 검토할 때는 같은 핵심 작업을 중립 UI와 Kook UI에서 수행하게 하여 장식이 이해와 재개를 돕는지 확인한다. B·S·P는 각각 별도 검증을 거친다. 다음 항목은 **모듈 채택 후 작성할 인수 기준의 초안**이며 기존 AC01~27에 추가된 출시 조건이 아니다.

- **N-AC01:** 사용자는 첫 화면에서 프로젝트 시작·샘플 체험·저장 상태를 도움 없이 찾는다.
- **N-AC02:** 캐릭터 표현을 껐다 켜도 카드·영역·장면·메모와 다음 행동이 동일하다.
- **N-AC03:** 200% 확대, 동작 줄이기, 키보드·목록 보기에서도 중단·재개를 완료한다.
- **N-AC04:** 저장 실패·권한 상실·파일 누락을 이야기 연출 없이 정확히 이해한다.
- **B-AC01:** 이동 중 수집한 항목을 프로젝트 미지정 상태로 보관하고 나중에 책상에 놓을 수 있다.
- **S-AC01:** 사용자가 선택하지 않은 로컬 원본과 폴더 핸들은 서버로 전송되지 않는다.
- **S-AC02:** 오프라인·충돌·동기화 실패 때 항목이 조용히 사라지거나 덮어써지지 않는다.
- **P-AC01:** 공개 대상과 범위를 사전에 확인하고 링크를 취소할 수 있다.

채택 판단에는 분위기에 대한 선호도와 별개로 첫 작업 시간, 중단 기록 시간, 며칠 뒤 재개 시간·성공률, 실패 상태 이해도를 함께 사용한다. 표현 때문에 핵심 흐름이 느려지거나 데이터를 오해한다면 N의 강도를 낮춘다. B는 실제 이동 중 수집 빈도와 책상에서 다시 꺼내 쓰는 비율을 확인한 뒤 범위를 정한다.

## 8. 제안 실행 순서와 미결정 사항

1. 기존 웹 PRD의 재방문 흐름과 저장 신뢰를 완성한다.
2. B의 모바일 흐름을 프로토타입으로 검증하고 실제 수집 형식을 좁힌다. S의 동기화 대상·계정·동의·충돌 정책을 별도 PRD로 확정한다.
3. N의 저비용 화면 시안과 샘플 책상으로 이야기의 이해도를 검증한다. N은 B·S와 독립적으로 채택하거나 제외한다.
4. P의 외부 공개가 필요한지 결정한다. 필요할 때만 별도 공개 PRD와 인수 기준을 확정한다.

아직 정하지 않은 사항은 Kook의 최종 외형과 목소리, 이야기 표현의 기본 켜짐 여부, 모바일 수집 형식, 계정 필요성, 동기화 대상, 외부 공유 범위다. 이 항목은 디자인·기술 결정 전에 사용자 검증과 범위 합의가 필요하다. 합의 전에는 기능 약속이나 출시 일정으로 사용하지 않는다.
