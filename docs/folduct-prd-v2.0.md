# Folduct PRD 2.0 — 돌보는 작업방

버전 2.0 · 작성일 2026년 10월 18일 · 대상 기획 디자인 개발 검증 담당

**이 문서가 Folduct의 기준 문서다.** [WEB PRD 1.0](./folduct-web-prd-v1.0.md)의 FR01~14·AC01~27은 이 문서 6장 표에 적은 변경점을 빼고 그대로 유효하며, 세부 수치·예외 규칙은 1.0 본문을 따른다. 1.0과 이 문서가 충돌하면 이 문서가 우선한다. [책상·가방·Kook 검토안](./folduct-kook-optional-module-draft.md)의 V 모듈은 이 문서의 FR15~19로 흡수·대체된다. N(Kook)·B(가방)·S(동기화)·P(공유)는 그대로 후속 검토안이다.

## 1 하나의 컨셉

> **Folduct는 프로젝트마다 방을 하나 준다. 방은 내가 무엇을 쓰고, 무엇을 놔뒀고, 얼마나 찼는지 스스로 보여준다. 일주일에 한 번 방이 정리되어, 다시 들어왔을 때 남아 있는 것이 곧 지금 중요한 것이 된다.**

1.0의 중심이던 ‘중단한 작업 다시 시작하기’와 새로 더한 ‘꾸준한 관리’는 따로 노는 기능이 아니라 하나의 루프다.

```
들어오기(이어서 시작) → 쓰기(놓기·메모) → 나가기(여기서 멈추기)
        ↑                                         ↓
   주간 정리(상자) ←── 쓰지 않은 물건은 기울고 쓰러진다 ←──┘
```

- **재개**는 ‘무엇을 보고 있었고 왜 골랐고 이제 뭘 할까’를 되찾는다.
- **돌봄**은 그 판단을 방해하는 잡음(안 쓰는 자료, 과하게 커진 방)을 꾸준히 걷어낸다.
- 두 기능은 같은 데이터(‘손댄 시각’, 파일 용량, 장면)를 쓴다.

### 은유와 실제 동작의 대응

은유는 장식이 아니라 동작과 1:1로 대응해야 한다(1.0의 인터랙션 언어 원칙 유지).

| 은유 | 실제 동작 |
| --- | --- |
| 방 | 프로젝트 작업면 |
| 물건 | 카드(파일 참조 또는 메모) |
| 물건 크기 | 파일 용량 단계 |
| 방 크기 | 사용자가 정한 용량 예산 |
| 기울어짐·쓰러짐 | 일정 기간 손대지 않은 카드 |
| 정리 상자 | 프로젝트 폴더 안의 실제 폴더 `_Folduct 정리상자` + 방 안의 상자 패널 |
| 주간 정리 | 일주일마다 쓰러진 카드의 파일을 사용자 확인 뒤 상자 폴더로 실제로 옮김 |
| 방을 나서며 남기는 쪽지 | 여기서 멈추기 + 다음 행동 |
| 집 | 모든 방이 보이는 첫 화면 |

UI 문구의 톤은 **돌봄**이다. 꾸짖지 않는다. ‘엄마가 방을 치운다’는 내부 기획 비유이며 화면에는 ‘주간 정리’로 쓴다.

### 시각 언어 — 차 한 잔

2026-10-18 사용자가 고른 참고 그림(녹차 티백과 찻잔, 테라코타 위 주전자와 찻잔)을 기준으로 한다. 돌봄의 톤을 ‘차를 우리며 잠깐 방을 돌아보는 시간’으로 보여준다.

- **평면 오린 종이**: 그라데이션·흐린 그림자 대신 납작한 오프셋 그림자와 손으로 자른 듯 조금씩 다른 모서리.
- **팔레트**: 크림 종이(배경·카드), 테라코타(책상·방 바닥), 짙은 갈색(글자·손잡이), 올리브(주요 버튼·선택), 연두 티백(기울어짐 표시), 우린 차의 적갈색(쓰러짐 표시).
- **질감**: 종이 결 노이즈, 김처럼 보이는 망점(알림·상자 목록). 모두 외부 요청 없이 CSS로 만든다.
- 색만으로 뜻을 전하지 않는다(4장 기준 4). 기울기·라벨 글자가 항상 함께 간다.

## 2 누가, 왜 쓰는가

### 주 사용자

| 사용자 | 상황 | Folduct가 주는 것 |
| --- | --- | --- |
| **디자인·미디어 전공 학생** (1차 타깃, 1.0과 동일) | 수업·개인 프로젝트 2~5개 동시 진행, 영상·PSD 등 큰 파일, 학기마다 폴더가 쌓임 | 며칠 쉬어도 바로 재개, 어떤 과제가 용량을 먹는지 한눈에 |
| **프리랜서 디자이너·영상 편집자** | 클라이언트별 폴더, 시안·버전이 계속 늘어남, 디스크가 자주 참 | 프로젝트별 용량 예산과 주간 정리로 ‘어느 클라이언트 폴더를 비울지’ 판단 |
| **1인 크리에이터** | 원본 촬영본이 수십 GB, 편집 중 레퍼런스가 흩어짐 | 큰 물건이 눈에 띄고, 이번 주 안 쓴 촬영본이 자동으로 모임 |

### 맞지 않는 사용자 (범위 밖)

- 개발자 저장소(.git·node_modules는 스캔 제외), 팀 공동 작업, 수만 개 자산을 관리하는 DAM 사용자
- 파일을 자동으로 **지워** 주길 원하는 사용자. Folduct는 상자 폴더로 옮기기만 하고 삭제는 사용자가 Finder에서 한다(4장 기준 1)
- Safari·Firefox 사용자는 실제 파일 이동을 쓸 수 없다(Folduct 안에서만 정리, 6.4)

### 쓰는 이유 — 기대 효과

1. **다시 열었을 때 덜 헤맨다.** 안 쓰는 카드가 상자로 빠져 있으므로 방에 남은 것이 곧 현재 작업 자료다. 재개 요약(마지막 카드·이유·다음 행동)이 잡음 없이 읽힌다.
2. **정리가 의지가 아니라 리듬이 된다.** 사용자가 날을 잡아 치우지 않아도 일주일마다 후보가 모이고, 30초 안에 ‘두기/돌려놓기/빼기’만 고르면 된다.
3. **용량을 숫자가 아니라 감각으로 안다.** 큰 파일은 큰 물건으로 보이고 방이 차오르는 것이 보인다. 디스크가 꽉 차기 전에 어느 프로젝트가 원인인지 안다.
4. **정리가 실제로 되고, 무섭지 않다.** 안 쓴 파일이 실제 폴더에서 `_Folduct 정리상자`로 모인다. 그래도 지우지는 않고, 확인 뒤에만 옮기며, ‘제자리로’ 한 번이면 원래 위치로 돌아간다.

## 3 핵심 루프의 사용자 시나리오

1. 월요일, 학생이 Folduct를 연다. 집 화면에 “이번 주 정리” 모달: ‘졸업전시’ 방에서 쉬고 있던 파일 4개(1.8GB)를 정리 상자로 옮길까요?
2. 레퍼런스 하나는 체크를 빼고 ‘정리하기’. 브라우저가 폴더 수정 권한을 묻고, 허용하면 파일 3개가 실제 폴더의 `졸업전시/_Folduct 정리상자/`로 옮겨진다. 20초.
3. Finder에서 상자 폴더를 열어 보고, 필요 없는 촬영본은 직접 휴지통에 버린다(Folduct는 지우지 않는다).
4. 방에 들어가 ‘폴더 새로고침’ → “3.1GB / 5GB, 지난 확인보다 1.2GB 줄었어요.”
5. 재개 요약에서 마지막 카드와 다음 행동 “도입부 10초 줄이기”를 보고 바로 작업 시작.
6. 작업을 마치며 ‘여기서 멈추기’로 다음 행동을 남긴다.

## 4 제품 기준 (모든 기능이 지켜야 하는 규칙)

1. **원본은 옮기기만 하고, 지우거나 고쳐 쓰지 않는다.** 1.0의 ‘원본 쓰기·삭제·이동 제외’를 아래처럼 바꾼다.
   - 허용: 프로젝트 루트 아래 `_Folduct 정리상자` 폴더 만들기, 파일을 그 폴더로 옮기기, 원래 자리로 되돌리기.
   - 금지: 파일 삭제(웹의 `removeEntry`는 휴지통을 거치지 않는 영구 삭제다), 내용 쓰기, 루트 밖으로 옮기기, 폴더 통째로 옮기기, 덮어쓰기.
   - 옮기기 전에 목록을 보여주고, 사용자가 누른 ‘정리하기’ 안에서 쓰기 권한을 요청한다. 앱이 스스로 옮기지 않는다.
   - 삭제는 사용자가 Finder에서 상자 폴더를 비우는 방식으로 한다.
2. **되돌릴 수 없는 동작은 없다.** 주간 정리 직전에는 안전 장면을 남긴다. 상자로 간 파일은 원래 경로를, 카드는 원래 위치를 기억해 ‘제자리로’로 둘 다 돌아간다. 이동은 기록을 먼저 남기고 하므로 중간에 앱이 꺼져도 다음 실행 때 실제 위치를 확인해 맞춘다. 자동 삭제는 어떤 경우에도 없다.
3. **사용자가 정한 배치를 몰래 바꾸지 않는다.** 기울어짐은 표시 효과이며 저장 좌표를 바꾸지 않는다. 용량 단계는 카드를 **처음 놓을 때의 기본 크기**와 카드 안 아이콘에만 쓰고, 사용자가 조정한 크기는 덮어쓰지 않는다.
4. **효과만으로 뜻을 전하지 않는다.** 기울기·크기·색에는 항상 글자(‘7일째 그대로’, ‘1.2GB’)가 붙는다. 움직임 줄이기에서는 기울기 대신 라벨만 쓴다. 목록 보기에서도 같은 정보가 보인다.
5. **값의 뜻을 하나로 고정한다.** ‘크기’는 저장 용량(바이트), ‘방치’는 Folduct 안에서 손대지 않은 기간이다. 파일 수·활동 빈도와 섞지 않는다.
6. **Folduct 안에서 본 것만 센다.** OS나 다른 앱의 행동은 추적하지 않는다. 원본 수정 시각은 스캔 메타데이터로만 보조 신호로 쓴다.
7. **모르면 모른다고 표시한다.** 부분 스캔·권한 상실이면 ‘최소 n 확인’으로 쓰고 경고·판정을 하지 않는다.
8. **잔소리하지 않는다.** 주간 보고는 주 1회, 언제든 미룰 수 있고, 쉬는 방과 고정한 물건은 판정하지 않는다. 경고는 작업을 막지 않는다.
9. **로컬 우선, 무료 우선.** 서버·계정 없이 동작한다. 앱이 꺼져 있을 때의 알림(푸시·문자·메일)은 없고, 모든 판정은 앱을 연 시점에 계산한다.

### 웹에서 가능한 범위

실제 파일 이동은 Chrome·Edge의 File System Access API(`FileSystemFileHandle.move`)에 기댄다. Safari·Firefox, 그리고 폴더 입력 방식으로 연결한 방은 이동할 수 없으므로 Folduct 안에서만 정리한다(‘virtual’ 상자). 휴지통 보내기, Finder에서 위치 열기, 실시간 변경 감지는 웹에서 할 수 없다. 자세한 표와 검증 방법은 [방 돌보기 구현 지시서](./cursor-room-care-prompts.md) 1장에 있다.
10. **재개를 해치지 않는다.** 정리·경고 연출 때문에 저장 확인이나 재개 요약이 늦어지면 안 된다.

### 6.2 FR15 손댄 시각과 방치 판정 P0

**손댄 시각(lastTouchedAt)** 은 카드별로 아래 행동이 있었던 마지막 시각이다.

| 손댄 것으로 셈 | 세지 않음 |
| --- | --- |
| 이동·크기 조정·구역 이동 | 호버, 선택만 하기 |
| 제목·메모 편집 | 방 스크롤·확대 |
| 미리보기 열기 | 자동 저장, 새로고침, 폴더 재스캔 |
| 상자에서 ‘제자리로’ | 장면 열람(읽기 전용) |

**판정은 ‘방을 쓴 날’ 기준이다.** 카드는 “방에서 다른 무언가를 손댄 날이 있는데, 이 카드는 그동안 손대지 않았을 때”만 방치로 본다. 방 자체를 아예 안 연 기간은 방치가 아니다. 그 방은 집에서 ‘쉬는 방 · 12일 전 마지막 작업’으로 표시된다. 휴가 뒤 돌아왔을 때 전부 쓰러져 있는 일을 막는다.

| 단계 | 조건 (기본값) | 표시 |
| --- | --- | --- |
| 정상 | 손댄 뒤 3일 미만 | 기본 |
| 기울어짐 | 손댄 뒤 3일 이상, 그 사이 방을 쓴 날 있음 | 약 8° 기울기 + ‘3일째 그대로’ |
| 쓰러짐 | 손댄 뒤 7일 이상, 그 사이 방을 쓴 날 있음 | 눕혀진 모양 + ‘7일째 그대로 · 다음 정리 때 상자로’ |

- **예외**: 고정한 카드(pinned), 쉬는 중인 방, 누락·권한 필요 상태의 카드, 원본 수정 시각이 손댄 시각보다 최근인 파일 카드(밖에서 작업 중일 수 있음).
- 상세 패널에는 두 값을 따로 보여준다: “Folduct에서 9일째 그대로 · 원본은 2일 전 수정됨”.
- 단계는 저장하지 않고 열 때마다 계산한다.

### 6.3 FR16 물건 크기와 방 용량 P0

**물건 크기 단계** — 로그 단계다. 선형이면 4GB 영상 하나가 나머지를 모두 가린다.

| 단계 | 파일 용량 | 아이콘 배율 | 새 카드 기본 크기 |
| --- | --- | --- | --- |
| 1 | 1MB 미만 | 1.0× | 240 × 180 |
| 2 | 1–10MB | 1.15× | 260 × 195 |
| 3 | 10–100MB | 1.3× | 290 × 218 |
| 4 | 100MB–1GB | 1.5× | 330 × 248 |
| 5 | 1GB 이상 | 1.75× | 380 × 285 |

- 메모 카드는 단계 1이다.
- 기본 크기는 **처음 놓을 때만** 적용한다. 이후에는 사용자가 정한 크기가 우선이다(1.0의 180×120~600×600 범위 유지).
- 용량이 바뀐 파일은 아이콘 배율만 바뀌고 카드 크기는 그대로다.
- 정확한 값(“1.2GB”)을 항상 함께 표시한다.

**방 용량**

- **기준값**: 이 방에 연결된 폴더에서 스캔으로 확인한 파일 용량 합계. 같은 파일은 한 번만 센다. 스캔 제외 항목(숨김·.git·node_modules)은 빼고, 그 사실을 표시한다.
- **방 크기 정하기**: 폴더 연결 직후 “지금 2.1GB예요. 방 크기를 3GB로 할까요?”처럼 현재 용량 × 1.5를 반올림해 제안한다. 프리셋 1GB / 5GB / 20GB와 직접 입력, ‘정하지 않음’도 제공한다. 정하지 않으면 용량은 보여주되 경고는 하지 않는다.
- **표시**: 집과 방 상단의 막대, 방 배경 아래쪽에 사용률만큼 차오르는 옅은 채움.

| 사용률 | 동작 |
| --- | --- |
| 80% 이상 | 막대 강조 + “방이 거의 찼어요” 문구 (모달 없음) |
| 100% 이상 | 방을 열 때 주 1회 배너: 가장 큰 파일 5개 + ‘경로 복사’ + ‘방 크기 늘리기’ + ‘이번 주 숨기기’ |

- 경고는 작업을 막지 않는다. 앱이 꺼져 있을 때 알림(문자 등)은 보내지 않는다.
- 재스캔으로 용량이 줄면 “이번 주 1.2GB 비웠어요”를 보여준다. 이전 합계는 Root에 저장한다.

### 6.4 FR17 주간 정리 P0

**실행 시점**: 마지막 정리 후 7일이 지난 뒤 처음 집(S01)을 열 때 후보를 계산해 모달을 연다. 앱을 오래 안 열었다면 밀린 주를 한 번에 처리한다. 집 상단의 ‘주간 정리’ 버튼으로 언제든 직접 열 수도 있다.

**후보**: 돌보기가 켜져 있고 쉬는 중이 아닌 방의 ‘쓰러짐’ 파일 카드. 메모 카드(파일 없음), 고정·누락 카드는 뺀다. 같은 파일을 여러 카드가 쓰면 그 카드가 **모두** 쓰러졌을 때만 후보다.

**S08 주간 정리 모달 — 옮기기 전에 묻는다**

```
이번 주 정리 · 10월 13일 – 10월 19일
선택한 파일을 각 프로젝트 폴더의 ‘_Folduct 정리상자’로 옮겨요. 지우지 않아요.

졸업전시 — 쉬고 있던 파일 4개 (1.8GB)
  [✓] 레퍼런스_v2.psd   7일째 그대로 · 820MB
        “표지 색감 참고용” ← 이유 메모 첫 줄
  [ ] 표지_시안3.png    9일째 그대로 · 12MB
  ...
영상수업 — 방이 거의 찼어요  4.3GB / 5GB   [큰 물건 보기]

[정리하기]   [다음 주에]
```

**‘정리하기’를 누른 뒤** (방마다, 방 하나의 실패가 다른 방에 번지지 않음):

1. 그 클릭 안에서 방 폴더의 쓰기 권한을 요청한다. 거부되면 그 방은 옮기지 않는다.
2. 현재 작업을 안전 장면(‘주간 정리 전 …’)으로 저장한다. 실패하면 그 방은 옮기지 않는다.
3. 파일마다: ‘이동 중’ 기록 → `_Folduct 정리상자/<원래 하위 경로>`로 이동 → 자료 경로 갱신과 ‘상자 안’ 기록. 같은 이름이 있으면 `이름 (2)`로 피한다.
4. 카드는 방에서 숨긴다. 카드·메모·좌표는 지우지 않는다.
5. 실제 이동을 못 하는 방(Safari·Firefox, 폴더 입력 방식)은 기록만 남기는 ‘virtual’ 상자로 정리하고 “이 방은 Folduct 안에서만 정리했어요. 실제 파일은 그대로예요.”라고 쓴다.
6. 결과: “졸업전시 3개 옮김(1.8GB) · 1개 실패(같은 이름 파일이 열려 있음)”.

- ‘다음 주에’는 아무것도 옮기지 않는다.
- 후보가 없는 주에는 모달 대신 토스트로 “이번 주는 치울 게 없었어요”를 띄운다.
- 같은 주에 모달은 한 번만 자동으로 뜬다.

### 6.5 FR18 정리 상자 P0

- 상자는 방마다 하나다. 구역 8개 한도에 포함하지 않는다.
- **제자리로**: 파일을 원래 경로로 다시 옮기고(쓰기 권한 확인), 카드를 원래 위치에 다시 보이며 손댄 시각을 갱신한다. 원래 자리에 같은 이름 파일이 있으면 되돌리지 않고 알린다. 원래 구역이 삭제됐으면 원래 절대 좌표로 돌아간다. virtual 상자는 기록만 지운다.
- **카드 빼기**: 카드만 삭제한다. 파일은 상자 폴더에 그대로 남는다. 메모가 있는 카드는 한 번 더 확인한다.
- **경로 복사**: 상자 안 실제 경로를 복사한다. 패널 하단에 “Folduct는 파일을 지우지 않아요. 필요 없으면 Finder에서 ‘_Folduct 정리상자’를 비워 주세요.”
- **사용자가 Finder에서 상자를 비우면**: 다음 폴더 새로고침에서 해당 자료가 누락(missing)으로 바뀐다. 카드와 메모는 남고 누락 표시가 붙는다(1.0 FR11).
- **오래 상자에 있던 물건**: 4주 넘게 상자에 있으면 다음 주간 보고에서 “빼도 될까요?” 묶음으로 한 번 제안한다. 자동 삭제는 없다.
- 상자 안 카드도 검색 결과에 나온다. ‘상자 안’ 표시가 붙고, 선택하면 ‘제자리로’를 제안한다.
- 재개 요약의 마지막 선택 카드가 상자로 갔다면 요약에 “상자로 옮겨진 카드”로 표시한다.

### 6.6 FR19 방 설정 P0

방마다 아래 항목을 둔다. 끄거나 바꿔도 카드·메모·장면 데이터는 바뀌지 않는다.

| 항목 | 기본값 |
| --- | --- |
| 방 돌보기 | 켜짐. 손댄 시각은 방을 처음 연 때부터 세므로 기존 방도 바로 쓰러지지 않는다 |
| 쉬는 중 | 꺼짐 |
| 기울어짐 / 쓰러짐 기준일 | 3 / 7 |
| 방 크기 | 연결 시 제안값 또는 없음 |
| 정리 요일 | 월요일 (앱 전체 설정) |

## 7 데이터 모델 변경

**카드·프로젝트 스키마는 바꾸지 않는다.** 카드 검사는 정확한 키 목록으로 하고 장면 스냅샷도 같은 검사를 거치므로, 카드에 필드를 더하면 장면·백업·검증이 함께 흔들린다. 돌보기 상태는 기존 `settings` 스토어에 방마다 하나의 기록으로 둔다. IndexedDB 스키마 버전은 그대로다.

```ts
// settings 스토어, key = `care:${projectId}`
type CareRecord = {
  key: string;
  enabled: boolean;
  resting: boolean;
  tiltAfterDays: number;              // 3
  fallAfterDays: number;              // 7
  budgetBytes: number | null;
  lastScanBytes: number | null;       // ‘지난 확인보다 n GB 줄었어요’ 비교용
  touched: Record<string, number>;    // cardId → 손댄 시각
  pinned: string[];
  boxed: Record<string, {             // assetId → 상자 기록
    state: "moving-in" | "boxed" | "moving-out" | "virtual";
    fromPath: string;
    boxPath: string;
    at: number;
  }>;
};

// settings 스토어, key = "care:sweep"
type SweepRecord = { key: "care:sweep"; lastSweepAt: number | null; weekday: number };
```

- 방을 쓴 날은 이미 구현된 `activity:<projectId>`(최근 30일 작업일)를 그대로 쓴다.
- 상자로 간 파일은 자료(Asset)의 `relativePath`를 상자 경로로 바꾼다. 같은 assetId를 유지하므로 메모·장면 참조가 끊기지 않는다.
- 방치 단계, 용량 합계, 사용률은 저장하지 않고 계산한다.
- 카드를 숨기는 것은 `boxed`에 그 카드의 assetId가 있는지로 판단한다. 작업면 데이터는 바뀌지 않는다.

## 8 인수 기준 (추가)

- **AC28** 기울어짐·용량 표시를 켜고 끄기 전후로 카드의 저장 좌표·크기·구역이 동일하다.
- **AC29** 호버·스크롤·새로고침·재스캔만 한 카드는 lastTouchedAt이 바뀌지 않는다. 이동·메모·미리보기는 바뀐다.
- **AC30** 방을 14일 동안 열지 않은 뒤 돌아와도 카드가 쓰러져 있지 않다.
- **AC31** 주간 정리 직전 ‘주간 정리 전’ 안전 장면이 생긴다. 안전 장면 저장이 실패한 방은 파일을 옮기지 않는다.
- **AC32** ‘제자리로’는 파일을 원래 경로로, 카드를 원래 x, y, zoneId로 되돌린다. 구역이 삭제됐으면 절대 좌표로 돌아간다. 원래 자리가 점유돼 있으면 아무것도 옮기지 않는다.
- **AC33** 앱 소스 어디에서도 `removeEntry`·`createWritable`을 원본 폴더에 쓰지 않는다. 이동 대상은 프로젝트 루트 아래 `_Folduct 정리상자` 안과 원래 경로뿐이다.
- **AC34** 부분 스캔 방은 용량 경고 없이 ‘최소 n 확인’을 표시한다.
- **AC35** 쉬는 방, 고정 카드, 누락 카드는 상자로 가지 않는다.
- **AC36** 같은 주에 보고 모달은 한 번만 뜬다. 밀린 여러 주도 한 번에 처리된다.
- **AC37** 움직임 줄이기와 스크린리더에서 방치 단계와 용량을 글자로 읽을 수 있다.
- **AC38** 백업 왕복 후 상자 상태·원래 위치·방 설정이 보존된다.
- **AC39** 사용자가 ‘정리하기’를 누르기 전, 또는 쓰기 권한을 거부했을 때 어떤 파일도 옮겨지지 않는다.
- **AC40** 이동 도중 탭을 닫았다 다시 열면, 파일이 실제로 있는 위치(원래 경로 또는 상자)에 맞춰 기록이 복구된다. 이름 충돌 시 기존 파일을 덮어쓰지 않는다.

## 9 보강해야 할 점 — 아직 ‘왜 써야 하지?’가 약한 곳

이 장은 미해결 과제다. 출시 전에 하나씩 결정하거나 검증한다.

### 9.1 정리가 실제 폴더에 반영되는가 — 2026-10-18 결정

**결정: 보강안 B를 채택했다.** Chrome·Edge에서는 사용자 확인 뒤 파일을 프로젝트 안 `_Folduct 정리상자`로 실제로 옮긴다(4장 기준 1, FR17). 지원하지 않는 환경은 A(Folduct 안에서만 정리)로 떨어진다.

남은 한계와 확인할 것:

- **용량은 아직 줄지 않는다.** 옮기기만 하므로 사용자가 Finder에서 상자를 비워야 디스크가 비워진다. 이 한 단계를 사용자가 실제로 하는지 실험에서 본다.
- **열려 있는 파일**: Photoshop·Premiere가 열고 있는 파일은 OS가 이동을 막을 수 있다. 실패로 표시하고 다음 주에 다시 후보로 둔다.
- **다른 앱의 참조 끊김**: Premiere 프로젝트처럼 파일 경로를 기억하는 앱은 옮긴 파일을 찾지 못할 수 있다. 모달에 “다른 앱에서 쓰는 파일이면 체크를 빼 주세요”를 넣고, 영상·프로젝트 파일 사용자의 반응을 실험에서 확인한다.
- **macOS 휴지통과 다르다**: 상자는 프로젝트 폴더 안에 있으므로 용량을 계속 차지한다. 이 점을 상자 패널에 항상 적는다.

### 9.2 첫 주에는 보여줄 게 없다

방치는 7일이 지나야 생긴다. 첫 사용에서 ‘돌보는 방’의 가치를 느끼기 어렵다.

- **보강안**: 폴더 연결 직후 원본 수정 시각을 써서 “이 폴더에서 30일 넘게 수정되지 않은 파일 120개 (3.4GB)” 같은 **첫날 진단**을 보여준다. 카드가 아니라 폴더 전체 기준이므로 FR15 판정과 섞지 않고 별도 보고로 둔다.

### 9.3 카드로 올린 것만 관리된다

폴더에 1,000개가 있어도 방에 올린 카드 10개만 쓰러진다. 정작 폴더를 무겁게 만드는 것은 카드로 올리지 않은 파일일 수 있다.

- **보강안**: 9.2의 진단을 주간 보고에도 넣는다(“방 밖 오래된 파일”). 다만 원본 수정 시각만 근거로 하므로 ‘방치’가 아니라 ‘오래 수정 안 됨’이라고 정확히 쓴다.

### 9.4 Folduct를 매주 열 이유가 정리뿐이면 약하다

방치 판정과 주간 정리는 Folduct를 실제로 쓰는 사람에게만 의미가 있다. 작업은 Photoshop·Premiere에서 하고 Folduct는 가끔 여는 사용자에게는 데이터가 쌓이지 않는다.

- **보강안**: 재개 요약을 ‘작업 시작 버튼’으로 강화한다. 다음 행동 옆에 ‘원본 폴더 열기 / 경로 복사’를 둬서, 작업을 시작할 때 Folduct를 거치는 습관을 만든다. 1.0의 범위 밖인 외부 앱 실행은 하지 않는다.
- 원본 수정 시각이 최근인 파일은 쓰러뜨리지 않는 FR15 예외로, 밖에서 하는 작업이 오판되지 않게 한다.

### 9.5 경쟁 도구와 무엇이 다른지 한 문장이 필요하다

- 용량 분석은 macOS 저장 공간 관리, DaisyDisk, WinDirStat이 더 정확하다.
- 자료 수집·주석은 Eagle이 더 강하다.
- **Folduct만의 답**: “**왜 남겨뒀는지(메모)와 다음에 뭘 할지(다음 행동)를 아는 상태에서 정리한다.**” 상자 목록과 보고 모달에 카드 메모 첫 줄을 함께 보여줘야 이 차별점이 화면에 드러난다. → FR17 보고 모달과 S07 상자 목록에 메모 첫 줄을 표시하도록 반영했다.

### 9.6 방 크기를 정할 근거가 없다

사용자는 ‘이 프로젝트에 5GB가 적당한가’를 모른다. 임의의 숫자는 무시되거나, 매주 경고만 뜨는 원인이 된다.

- **보강안**: FR16의 ‘현재 × 1.5’ 제안으로 시작하고, 경고가 3주 연속 무시되면 “방 크기를 n GB로 늘릴까요?”를 한 번 묻는다.

### 9.7 정리한 보람이 보이지 않는다

치워도 피드백이 ‘상자 n개’뿐이면 동기가 약하다.

- **보강안**: 집 화면 방 오브제에 정돈 상태(‘쓰러진 물건 0 · 깨끗한 방’)를 글자로 보여주고, 주간 보고에 ‘지난주 대비’ 한 줄을 넣는다. 점수·연속 기록 같은 게임화는 잔소리 기준(4장 8)에 걸릴 수 있어 넣지 않는다.

### 9.8 브라우저에 묶인 기록

기록은 그 브라우저 프로필에만 있다. 컴퓨터를 바꾸거나 다른 브라우저로 열면 주간 리듬이 끊긴다. 1.0 FR13 백업 안내를 주간 보고 하단에 한 줄로 노출한다. 자동 동기화는 S 모듈 결정 전까지 하지 않는다.

## 10 검증

1.0 11장의 설계를 유지하고 아래를 더한다.

- **비교 과제**: 3주 사용 뒤, 돌보기를 켠 그룹과 끈 그룹이 “1주 이상 쉰 방을 다시 열고 첫 유효 작업을 시작하기까지 걸린 시간”을 비교한다.
- **보조 지표**: 주간 보고 완료율, ‘제자리로’ 비율(높으면 판정 기준이 너무 짧다는 뜻), 돌보기 끈 비율, 실제 용량 감소량(재스캔 기준).
- **채택 신호**: 재개 시간이 같거나 줄고, 보고 완료율 60% 이상, 돌보기 끈 비율 20% 미만, ‘제자리로’ 30% 미만.
- **기각 신호**: 기울기를 화면 오류로 오해함, 상자로 간 자료를 못 찾는 사례, 보고를 잔소리로 느낌.
- 실험 이벤트 추가: `sweep_run`, `sweep_report_closed`, `card_unboxed`, `card_removed_from_box`, `budget_warning_shown`. 파일명·경로·메모는 넣지 않는다(1.0 규칙).

## 11 개발 순서

단계별 프롬프트는 [방 돌보기 구현 지시서](./cursor-room-care-prompts.md)에 있다. 요약:

| 단계 | 내용 |
| --- | --- |
| C0 | 코드 점검 + 실제 Chrome에서 파일 이동 실험(테스트 폴더) |
| C1 | 손댄 시각 기록과 방치 판정 (화면 없음) |
| C2 | 기울어짐·쓰러짐 표시, 고정·쉬는 중, 방 설정 |
| C3 | 파일 이동 게이트웨이와 이동 기록 (화면 없음) |
| C4 | 주간 정리: 확인 → 권한 → 안전 장면 → 실제 이동 |
| C5 | 정리 상자 패널, 제자리로(실제 복원), 경로 복사 |
| C6 | 물건 크기 단계와 방 용량 |
| C7 | 실패·복구·접근성 마감, AC28~40 인수 검증 |

1.0 지시서의 6단계(권한 재연결)는 C3과 같은 권한 함수를 건드리므로, 두 작업을 동시에 진행하지 않는다.
