# Folduct 프로젝트 기획서

중단한 작업의 맥락을 되찾는 웹 작업공간

버전 1.0 · 작성일 2026년 10월 4일 · 대상 기획 검토자와 프로젝트 팀

## 1 프로젝트 개요

Folduct는 로컬 프로젝트 폴더에 자료의 배치, 선택 이유, 마지막 작업 상태와 다음 행동을 연결하는 웹 작업공간이다. 사용자가 며칠 뒤 프로젝트로 돌아왔을 때 이전 판단을 확인하고 작업을 이어갈 수 있게 한다. 첫 제품은 이미지·영상·문서를 함께 사용하는 디자인·미디어 전공 학생의 개인 프로젝트를 대상으로 한다.

핵심 개발 목표는 폴더 연결부터 자료 배치, 작업 중단 기록, 재방문 복원까지 한 흐름을 완성하는 것이다. 시각적 오브제와 공간 배치는 프로젝트를 구분하고 자료의 역할을 기억하는 단서로 사용한다. 제품 효과는 재시작에 걸린 시간과 기록에 든 수고를 함께 측정해 판단한다.

### 제안하는 사용자 가치

파일을 찾은 뒤에도 사용자는 어떤 시안을 선택했는지, 왜 선택했는지, 다음에 무엇을 해야 하는지 다시 확인해야 한다. Folduct는 이러한 판단을 해당 자료 옆에 남긴다. 기존 폴더와 제작 도구를 유지하면서 프로젝트의 맥락을 다시 읽을 수 있는 자리를 제공한다.

### 결과물과 제품 범위

- 데스크톱 브라우저에서 사용하는 개인용 웹앱과 시연용 샘플 프로젝트를 제작한다.
- 원본 폴더는 읽기 전용으로 연결하며, 배치·메모·장면은 브라우저에 저장한다.
- 사용자는 저장된 장면을 보고 현재 작업면으로 이어갈 수 있다.
- 별도 로그인과 서버 데이터베이스 없이 핵심 경험을 검증한다.

### 기획의 근거와 검증 상태

이 문서는 프로젝트 대화에서 도출한 문제 가설과 현재 웹 프로토타입의 코드 검토를 바탕으로 작성했다. 사용자 인터뷰, 시장 규모 조사, 경쟁 제품 비교 실험은 아직 수행하지 않았다. 문서의 성과 수치와 일정은 개발 및 검증 목표이며 달성 결과가 아니다.

함께 제공하는 Folduct WEB PRD 1.0은 화면, 기능 요구사항, 데이터 구조와 인수 기준을 정의한다. 본 기획서는 문제와 사용자 가치, 범위와 검증 계획을 설명하는 문서로 사용한다.

## 2 해결할 문제와 초기 사용자

### 작업을 재개하는 순간의 문제

사용자는 폴더 안에서 자료를 발견해도 그 자료가 현재 작업에서 어떤 의미인지 알기 어렵다. 레퍼런스, 검토 중인 시안, 이전 결과물이 함께 남아 있을 때 파일명이나 수정 시각만으로는 선택 이유와 다음 행동을 설명하기 어렵다. 이러한 맥락 복원에 시간이 든다는 것이 핵심 문제 가설이다.

예를 들어 미디어 프로젝트를 일주일 쉬었다가 열었을 때, 사용자는 영상 두 개를 다시 재생하고 메신저의 피드백을 찾아본 뒤에야 수정할 지점을 떠올릴 수 있다. Folduct는 영상 옆에 남긴 “도입부 축소” 메모와 다음 행동을 통해 이 과정을 줄이고자 한다.

### 초기 사용자와 사용 조건

첫 대상은 한 번에 2~5개의 수업·개인 프로젝트를 진행하고 이미지, 영상, PDF, 텍스트 자료를 함께 다루는 디자인·미디어 전공 학생이다. 작업을 하루 이상 중단했다가 돌아오는 경험이 있으며, 주로 개인 컴퓨터에서 파일을 관리한다는 조건을 초기 모집에 사용한다. 이 숫자는 전체 학생의 행동을 설명하는 통계가 아니다.

공동 편집, 모바일 중심 기록, 수만 개 파일을 관리하는 전문 자산 관리 업무는 첫 검증 대상에서 제외한다. 초기 사용 범위를 좁혀 공간 배치와 중단 기록이 실제로 도움이 되는지 확인한다.

### 사용자가 완료하려는 일

“며칠 전에 하던 프로젝트로 돌아왔을 때, 마지막으로 선택한 자료와 그 이유를 확인하고 다음 작업을 시작하고 싶다.”

이 요구에 대응하는 설계 가설은 세 가지다. 자료 옆의 이유 메모가 판단을 복원하고, 유지되는 위치가 자료의 역할을 구분하게 하며, 한 줄의 다음 행동이 작업 시작을 돕는다. 자동 요약이나 화려한 표현 없이도 이 가설을 먼저 검증할 수 있다.

### 대안과 비교할 지점

파일 탐색기와 별도 메모를 함께 사용하는 방식도 같은 문제를 해결할 수 있다. 따라서 Folduct의 비교 기준은 기능 개수나 최초 사용의 신기함이 아니라, 자료와 판단을 함께 보며 다시 시작하는 데 필요한 시간과 노력이다. 대체 도구의 기능 부재나 Folduct의 시장 우위를 전제로 하지 않는다.

## 3 핵심 경험과 시각적 설계

### 폴더 연결부터 작업 재개까지

1. 사용자가 프로젝트 폴더를 선택한다. 프로젝트 이름과 대표 이미지가 있는 오브제가 개인 책상에 생긴다. 책상은 작업 중인 프로젝트를 고르는 첫 화면이다.
2. 오브제를 열면 프로젝트 작업면이 나타난다. 기본 영역은 참고 자료, 진행 중인 작업, 검토할 후보이며 이름은 바꿀 수 있다.
3. 필요한 파일만 작업면에 놓고 이유를 적는다. 같은 파일을 여러 카드로 참조할 수 있으며 각 카드에는 서로 다른 메모를 붙일 수 있다.
4. 사용자가 ‘여기서 멈추기’를 누른다. 다음 행동을 선택적으로 한 줄 적고, 현재 배치·메모·선택 자료·미디어 재생 위치를 하나의 장면으로 저장한다.
5. 재방문하면 마지막 중단 시각, 다음 행동, 연결 상태가 보인다. 사용자는 ‘이어서 시작’을 누르고 마지막 작업 맥락을 확인한다.

### 작업 장면의 의미

장면은 특정 순간의 배치와 설명을 보존한 기록이다. ‘첫 아이디어’, ‘중간 피드백’, ‘최종 구성’처럼 이름을 붙여 판단의 흐름을 남길 수 있다. 과거 장면은 먼저 읽기 전용으로 확인하고, 원하면 복사해 현재 작업면으로 이어간다. 이어가기 전의 작업면은 안전 장면으로 남긴다.

장면은 원본 파일 내용을 복사하거나 버전을 보관하지 않는다. 파일이 외부에서 수정되었다면 현재 파일을 보여주면서 변경 사실을 알린다. 삭제되었거나 접근할 수 없으면 자리와 메모를 유지하고 다시 연결할 수 있게 한다.

### 공간과 오브제의 역할

프로젝트 오브제는 대표 이미지와 색을 통해 프로젝트를 구분한다. 사용자가 고른 표지와 위치는 임의로 변경하지 않는다. 작업면의 위치는 자료의 역할을 나타내며, 화면 크기가 바뀌어도 관계가 유지되도록 논리 좌표로 저장한다.

첫 화면은 읽기 쉬운 2차원 책상으로 제작한다. 선택 영역, 메모, 다음 행동이 장식보다 잘 보여야 한다. 기본 배치를 제공해 꾸미지 않고도 시작할 수 있게 하고, 키보드와 목록 방식으로도 자료를 배치할 수 있게 한다.

### 대표 시연

영상 프로젝트 폴더를 연결한 뒤 레퍼런스 두 개와 작업 영상 하나를 배치한다. “두 번째 시안의 도입부를 줄이기”를 남기고 중단한다. 앱을 다시 연 뒤 같은 배치와 메모를 확인하고 영상을 저장된 재생 위치에서 직접 재생한다. 시간 경과를 재현한 시연과 실제 며칠 후의 사용자 검증 결과는 구분해 제시한다.

## 4 개발 범위와 추진 계획

### 첫 출시의 필수 범위

필수 기능은 폴더 연결과 재연결, 프로젝트 책상, 파일 카드 배치, 카드 메모, 현재 작업 자동 저장, 중단 장면 저장, 재방문 이어가기, 장면 목록, 메타데이터 백업과 복원이다. 미리보기는 PNG·JPEG·WebP, 브라우저가 재생할 수 있는 영상·음원, 일반 텍스트를 중심으로 보장한다. PDF는 브라우저 기능을 이용하며 지원되지 않으면 별도 열기 안내를 제공한다.

지원하지 않는 문서도 파일명과 연결 카드를 남길 수 있다. 첫 버전은 모든 파일을 해석하려고 하지 않는다. 원본 수정·이동·삭제, 원본 버전 복구, 실시간 공동 편집, 클라우드 동기화, AI 요약, 3차원 물리 공간, 외부 편집기 상태 복원은 후속 검토 범위다.

### 현재 자산의 활용

기존 웹 프로토타입의 React·TypeScript 기반 화면, 폴더 선택, 파일 형식 분류와 일부 미리보기 코드를 재사용한다. 새로 개발해야 할 핵심은 프로젝트와 파일의 안정적 식별, 공간 배치 모델, IndexedDB 저장소, 장면 복원, 연결 실패 처리다. 현재의 수정 시각 기반 파일 ID는 장기 참조에 적합하지 않아 교체한다.

### 6주 실행안

- 1주차에는 대상 사용자 5명의 중단·재개 경험을 확인하고 클릭형 흐름과 파일 재연결 기술 실험을 끝낸다.
- 2주차에는 프로젝트 생성, 폴더 연결, 기본 작업면과 카드 배치를 구현한다.
- 3주차에는 메모, 자동 저장, 저장 상태 표시와 중단 장면을 구현한다.
- 4주차에는 장면 이어가기, 파일 변경 감지, 재연결과 메타데이터 백업·복원을 완성한다.
- 5주차에는 실패 상황과 접근성을 검증하고, 8~12명 규모의 비교 사용 실험을 시작한다.
- 6주차에는 재방문 실험을 마치고 결과에 따라 흐름을 수정한 뒤 시연과 결과 보고를 준비한다.

이 일정은 주당 20~25시간을 투입하는 개발 담당 1명과 기획·디자인·실험 진행 지원을 전제로 한 추정치다. 실제 담당자, 학사 일정과 숙련도에 따라 조정한다. 일정이 부족하면 장식과 추가 형식 지원부터 줄이고, 저장·복원·재연결 검증은 유지한다.

### 산출물과 운영

산출물은 웹앱, 샘플 프로젝트, 기획서, WEB PRD, 기능 검증 기록, 사용자 실험 결과와 시연 자료다. 배포는 HTTPS 정적 호스팅을 전제로 하되 실제 서비스 선택과 비용은 개발 착수 시 확인한다. 첫 제품에는 유료 AI API나 별도 데이터 서버가 필수로 필요하지 않다.

## 5 검증 계획과 성공 판단

### 비교 실험

초기 인터뷰 5명으로 문제가 발생하는 상황을 구체화하고, 별도 8~12명 규모의 사용 실험에서 기존 방식과 Folduct를 비교한다. 각 참여자는 난도가 비슷한 서로 다른 두 작업을 수행하고 2~3일 뒤 재개한다. 도구와 과제 순서를 교차 배정해 학습 효과를 줄인다. 작은 표본의 탐색 결과를 전체 사용자에 대한 확정적 효과로 해석하지 않는다.

재시작 시간은 프로젝트 접근을 시작한 순간부터 참여자가 올바른 자료와 다음 행동을 확인하고 첫 유효 작업에 착수한 순간까지 측정한다. 재연결에 든 시간도 포함한다. 단순히 ‘이어서 시작’을 누른 시각으로 대체하지 않는다. 시작 지연이나 실패가 발생한 사례도 함께 기록한다.

### 제안하는 성공 목표

- 재시작 시간은 참여자별 기존 방식 대비 변화율의 중앙값으로 계산하며, 30% 이상 감소를 목표로 한다. 실패 사례는 별도로 보고한다.
- 재개 과제는 사전 정의한 자료와 행동을 진행자의 도움 없이 확인한 경우 성공으로 보고, 시도 건수 중 80% 이상을 목표로 한다.
- ‘여기서 멈추기’의 입력·저장 시간 중앙값은 15초 이하를 목표로 한다. 메모 작성은 강제하지 않는다.
- 첫 폴더 선택부터 카드 3개와 이유 메모 1개가 저장될 때까지의 첫 사용 시간 중앙값은 3분 이하를 목표로 한다.
- 저장 완료로 표시한 기록이 새로고침·재연결·복원 시험에서 유실되는 결함은 출시 전에 모두 해결한다.

기록 시간뿐 아니라 배치와 관리에 드는 전체 수고도 관찰한다. 재시작이 빨라져도 준비 부담이 과도하면 기본 배치, 메모 입력 위치와 중단 흐름을 수정한다. 시간 단축이 관찰되지 않으면 장면 기능을 확장하기 전에 문제 가설을 다시 검토한다.

### 주요 위험과 대응

브라우저 권한이 만료되면 배치와 메모를 먼저 보여주고 폴더 재연결을 안내한다. 브라우저 데이터 삭제에 대비해 메타데이터 내보내기를 제공한다. 파일이 바뀌거나 없어지면 장면의 자리를 유지하며 현재 상태를 표시한다. 자동 저장 실패 시 성공으로 표시하지 않고 재시도와 백업 경로를 제공한다.

### 품질 평가 기준

최종 심사 기준안은 문제 검증 25점, 핵심 흐름 25점, 저장 신뢰성 20점, 사용성·접근성 15점, 시각적 일관성·발표 15점으로 구성한다. 각 항목은 실험 기록과 기능 검증 자료로 평가한다. 90점은 목표이며 현재 점수가 아니다. 저장 유실이나 원본 손상 결함이 있으면 합계와 관계없이 공개 시연 전 수정한다.
