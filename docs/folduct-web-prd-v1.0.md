# Folduct WEB PRD

작업 맥락 저장과 재개를 위한 웹 제품 요구사항

버전 1.0 · 작성일 2026년 10월 4일 · 대상 기획 디자인 개발 검증 담당

> 2026년 10월 18일: 기준 문서는 [PRD 2.0 — 돌보는 작업방](./folduct-prd-v2.0.md)이다. 이 문서의 FR01~14·AC01~27은 2.0 6장의 변경점을 빼고 유효하다.

2026년 10월 5일 제품 경계와 재개 요약 요구사항을 보강했다. 차별화는 경쟁 제품에 없는 단일 기능이 아니라 중단한 판단을 복원하는 전체 흐름으로 검증한다.

같은 날 **무료 우선 사용 경험과 작업 행동에 연결된 인터랙션**을 후속 설계 원칙으로 더했다. 운영 비용과 기기 간 동기화 비용이 확인되기 전까지 장기 무료 제공 범위를 확정했다고 표현하지 않는다.

작업한 날과 자료 규모를 오브제에 표현하는 V 모듈은 [별도 검토안](./folduct-kook-optional-module-draft.md)에 둔다. 2026년 10월 6일 선택형 시안이 웹 코드에 들어갔지만, 채도·두께 효과는 데이터 의미와 오해 가능성을 검증하기 전에는 P0 출시 요건이나 입증된 차별점으로 간주하지 않는다.

2026년 10월 5일 [책상·가방 후속 방향과 Kook 선택 스토리 명세](./folduct-kook-optional-module-draft.md)를 별도 문서로 추가했다. 모바일 가방과 웹 책상의 연결은 후속 제품 방향으로 기록하되 출시 단계와 상세 범위는 미정이다. **Kook 캐릭터·스토리 연출은 미채택 선택안**이다. 별도 문서는 본 PRD의 P0·P1 범위, FR01~14, AC01~27, 데이터 보존 정책과 개발 순서를 변경하지 않는다. Kook을 제외해도 책상·가방 기능의 방향을 유지할 수 있다.

## 1 제품 정의와 출시 범위

Folduct는 선택한 로컬 폴더를 읽고, 파일의 배치·이유 메모·다음 행동을 저장해 프로젝트를 다시 시작하도록 돕는 개인용 웹앱이다. 핵심 여정은 ‘폴더 연결 → 자료 배치와 메모 → 여기서 멈추기 → 재방문 → 이어서 시작’이다. 구현 우선순위는 이 흐름의 완결성과 저장 신뢰성에 둔다.

### 제품 경계와 차별화 가설

Folduct가 먼저 해결할 일은 자료를 대량 수집·분류하는 것이 아니라 **중단한 프로젝트에서 마지막 판단과 다음 행동을 되찾는 것**이다. 프로젝트를 다시 열었을 때 ‘무엇을 보고 있었나 → 왜 이 자료를 골랐나 → 이제 무엇을 할까’를 한 흐름으로 보여주는 경험을 검증한다. 카드 배치, 메모, 미리보기, 모바일 수집, 레트로퓨처리즘 표현은 각각 단독 차별점으로 주장하지 않는다. 특히 Eagle은 이미 수집·검색·미리보기·이미지와 영상 주석을 제공하므로, 파일 형식 수나 타임스탬프 메모로 경쟁하지 않는다. [Eagle 공식 기능 소개](https://eagle.cool/home), [Eagle 영상 주석 소개](https://en.eagle.cool/blog/post/the-ultimate-video-management-solution-for-creative-professionals-eagle-video-player) (2026-10-05 확인).

제품의 첫 화면과 시연은 ‘자료를 얼마나 잘 모으나’보다 ‘며칠 뒤 얼마나 적은 수고로 올바른 작업을 다시 시작하나’를 보여줘야 한다. 이 차이는 아직 사용자 실험으로 입증되지 않았다. Eagle을 이미 쓰는 창작자에게도 같은 중단·재개 과제를 수행하게 해 기존 방식과 비교한다.

### 무료 우선 사용 원칙

첫 검증 제품의 핵심 흐름인 폴더 연결, 배치·이유 메모, 중단·재개, 장면 열람, 메타데이터 백업·복원은 사용자에게 무료로 제공하는 것을 목표로 한다. 계정이나 결제를 핵심 재개 기능의 선행 조건으로 두지 않는다. 로컬 저장과 정적 웹앱을 우선하고 유료 AI API, 원본 파일 클라우드 보관, 대량 미디어 변환을 첫 제품의 필수 운영비로 만들지 않는다. 프로젝트·카드·장면의 초기 한도는 성능·저장 안전을 위한 설계값이며 유료 전환 장벽으로 사용하지 않는다.

무료가 제품 가치 전체를 설명하지는 않는다. 기기 간 자동 동기화는 서버 저장·인증·트래픽 비용을 만들 수 있으므로 B·S 후속 명세에서 전송 항목과 비용 상한을 측정한 뒤 무료 제공 범위를 결정한다. 우선 무료로 제공할 수 있는 수동 메타데이터 백업·가져오기와 자동 기기 간 동기화를 혼동하지 않는다. 운영 비용이 측정되지 않은 단계에서 ‘영구 무료 자동 동기화’를 약속하지 않는다. Eagle은 [30일 무료 체험](https://www.eagle.cool/download) 뒤 [일회성 유료 라이선스](https://www.eagle.cool/store)를 안내한다(2026-10-05 확인).

### 문서의 적용 범위

본 문서는 Folduct 프로젝트 기획서 1.0을 구현 가능한 요구사항으로 구체화한다. 현재 코드에 기능이 있다는 사실과 새 제품의 요구사항을 구분한다. P0는 사용자 검증 전 필수, P1은 P0 검증 이후, 제외는 이번 출시에서 구현하지 않는 기능이다. 수치 제한은 초기 제품의 설계값이며 실험 후 조정할 수 있다.

### P0와 후속 범위

P0는 프로젝트 생성, 폴더 연결·재연결, 책상 배치, 작업면의 카드·영역·메모, 검색, 기본 미리보기, 자동 저장, 장면 저장·이어가기, 안전 장면, 백업·복원, 오류 처리다. P1은 장면 비교, 확장된 문서 렌더러, 설치형 오프라인 실행과 더 큰 프로젝트 지원이다.

제외 범위는 원본 파일 쓰기·삭제·이동, 파일 버전 관리, 공동 편집, 계정·클라우드 동기화, AI 자동 해석, 외부 앱 실행·상태 복원, 3D 물리 엔진이다. 파일을 연결한 뒤 OS 전체나 다른 앱에서 수행한 행동을 추적하지 않는다.

### 후속 제품 방향: 웹 책상과 모바일 가방

웹은 자료를 펼치고 배치·판단·중단 기록을 남기는 책상, 모바일은 이동 중 떠오른 자료와 생각을 빠르게 담는 가방으로 구분한다. 가방과 책상은 사용자가 선택한 항목을 기기 간에 이어서 사용할 수 있어야 한다. 이 방향은 P0·P1의 출시 약속이 아니며, 실제 동기화에는 계정·원격 저장·전송 동의·충돌 처리의 별도 명세와 검증이 필요하다. 로컬 원본 폴더 전체와 폴더 핸들은 기본 공유 대상으로 삼지 않는다. 상세 요구사항과 Kook을 제거할 수 있는 표현 설계는 [별도 명세](./folduct-kook-optional-module-draft.md)를 따른다.

### 지원 환경과 용어

주 검증 대상은 Windows·macOS 데스크톱의 Chrome·Edge 최신 안정판이며 실제 검증 시 버전을 기록한다. API가 없는 환경은 폴더 입력 방식으로 폴백한다. Safari·Firefox에서는 지원 기능을 감지해 제한 모드로 동작하고 재방문 시 폴더 재선택을 안내한다. 휴대전화에서는 데모와 지원 안내만 제공하며 편집은 대상에서 제외한다.

‘책상’은 프로젝트 선택 화면, ‘작업면’은 프로젝트별 2차원 자료 공간이다. ‘카드’는 파일 참조 또는 독립 메모다. ‘장면’은 작업면 상태의 불변 기록이며 원본 파일 사본을 포함하지 않는다. ‘현재 작업’은 계속 자동 저장되는 편집 상태다.

## 2 정보 구조와 화면 요구사항

### S01 개인 책상

경로는 /desk다. 프로젝트 이름, 표지, 마지막 중단 시각, 다음 행동의 첫 줄, 연결 상태를 보여준다. ‘프로젝트 추가’와 각 프로젝트의 ‘이어서 시작’을 주요 행동으로 제공한다. 책상은 논리 좌표 1440 × 900을 사용하며 최초 배치는 빈 슬롯에 자동 배정한다. 사용자가 바꾼 위치와 표지는 이후 자동 정렬하지 않는다.

‘이어서 시작’은 최근 작업면을 열면서 마지막 선택 카드, 그 카드의 이유 메모, 다음 행동과 원본 접근 상태를 한곳에 모은 **재개 요약**을 보여준다. 해당 카드로 바로 이동하거나 요약을 닫고 저장된 작업면 전체를 볼 수 있다. 메모가 없으면 추측해 채우지 않고 빈 상태를 그대로 표시한다. 요약은 기존 Workspace·Scene 정보에서 구성하며 별도 필수 입력을 늘리지 않는다.

최대 12개 프로젝트를 초기 지원 범위로 한다. 한 화면에서 서로 가려지지 않도록 기본 배치를 제공하고, 책상이 불편한 사용자는 같은 프로젝트를 목록으로 선택할 수 있다. 기록이 없으면 샘플 체험과 내 폴더 연결을 보여준다. 데모 데이터는 실제 데이터와 저장 공간을 구분한다.

### S02 프로젝트 작업면

경로는 /projects/:projectId다. 상단에는 프로젝트명, 저장 상태, ‘장면’, ‘여기서 멈추기’를 둔다. 왼쪽에는 검색 가능한 자료 목록, 가운데에는 작업면, 오른쪽에는 선택 카드의 미리보기와 메모를 둔다. 오른쪽 패널은 선택 시 열리고 닫을 수 있다. 기본 영역은 ‘참고 자료’, ‘진행 중’, ‘검토 후보’다.

최소 편집 화면은 1024 × 720 CSS px로 한다. 폭 1024~1279에서는 양쪽 패널을 겹쳐 여는 방식으로 전환한다. 더 좁은 환경은 편집 제한 안내와 목록·메모 읽기를 제공하며 기존 위치를 재배치하지 않는다. 200% 확대에서도 주요 행동에 접근할 수 있도록 단일 패널 보기를 제공한다.

### 작업 행동에 연결된 인터랙션 언어

책상의 프로젝트를 **펼치기**는 작업면 열기, 자료를 **놓기**는 카드의 역할·위치 정하기, **접기**는 ‘여기서 멈추기’ 저장, **다시 펼치기**는 재개 요약에서 마지막 카드와 다음 행동 확인에 대응한다. 물리적 은유는 실제 동작과 일대일로 연결한다. 장식만 있는 드래그·숨겨진 제스처·강제 애니메이션을 필수 조작으로 만들지 않는다.

첫 구현은 기존 2차원 화면 위의 짧은 전환·집중 표시·오브제 반응 정도로 제한한다. 예를 들어 재방문 시 마지막 카드와 다음 행동이 함께 눈에 들어오도록 하고, 가방 항목을 책상에 놓는 후속 흐름에서는 놓인 위치와 프로젝트 소속이 즉시 확인되게 한다. 효과를 꺼도 같은 정보와 기능을 제공한다. 키보드·목록 보기·동작 줄이기 설정에서도 해당 행동이 가능해야 하며, 연출 때문에 저장 확인이나 작업 재개가 지연되어서는 안 된다. Kook 캐릭터를 채택하지 않아도 이 인터랙션 언어는 유지할 수 있다.

오브제의 채도와 크기로 데이터 값을 보여주려면 **무슨 값을 뜻하는지**를 먼저 고정한다. 활동 빈도, 마지막 작업 시각, 파일 수, 저장 용량은 서로 다른 데이터다. 표지 이미지나 카드 내용의 원래 색은 보존하고, 사용자가 정한 카드 크기와 책상 위치는 자동 데이터 표현이 덮어쓰지 않는다. 상세 설계·검증은 V 모듈에서 별도로 결정한다.

### S03 중단 기록과 S04 장면 목록

중단 기록은 다음 행동 200자와 선택적 장면 이름 60자를 입력하는 대화상자다. 기본 이름은 프로젝트명과 로컬 날짜·시각으로 생성한다. 다음 행동을 비워도 저장할 수 있다. 장면 목록에는 이름, 생성 시각, 유형과 카드 수를 표시한다. 유형은 중단 기록, 수동 기록, 안전 장면이다.

### S05 장면 열람과 S06 저장 관리

장면 열람 경로는 /projects/:projectId/scenes/:sceneId다. 읽기 전용 표시, 현재 원본을 참조한다는 안내, ‘이 장면에서 이어가기’를 제공한다. 저장 관리에서는 백업 내보내기, 가져오기, 프로젝트 제거를 제공한다. 프로젝트 제거는 삭제될 기록 수를 알려주고 확인 후 실행한다. 원본 파일은 제거 대상에 포함되지 않는다.

URL에는 폴더 경로나 메모를 넣지 않는다. 내부 식별자만 사용한다. 존재하지 않는 프로젝트·장면 주소는 빈 오류 화면 대신 책상으로 돌아갈 수 있는 안내를 제공한다.

## 3 프로젝트 연결과 자료 등록

### FR01 프로젝트 생성과 폴더 접근 P0

사용자가 ‘프로젝트 추가’를 누르면 읽기 전용 폴더 선택을 요청한다. API 지원 환경은 showDirectoryPicker를, 그 외 환경은 디렉터리 입력을 사용한다. 취소는 오류 알림 없이 이전 화면으로 돌아간다. 권한 거부는 이유와 재시도 행동을 표시하며 데이터가 없는 프로젝트를 중복 생성하지 않는다. 보안 컨텍스트와 사용자 동작 요건은 기술 참고자료 1을 따른다.

연결 후 프로젝트 이름과 표지를 확인한다. 이름은 1~80자이며 앞뒤 공백을 제거한다. 기존 핸들과 동일한 폴더로 확인되면 기존 프로젝트를 열도록 안내한다. 이름이 같다는 이유만으로 폴더가 같다고 판단하지 않는다. 폴백 모드는 중복 여부를 확정하지 않고 사용자에게 기존 프로젝트 재연결을 제안한다.

### FR02 자료 목록과 검색 P0

최대 파일 1,000개, 하위 폴더 깊이 10을 지원한다. 한도를 넘으면 부분 수집 상태와 미포함 이유를 표시하고 작은 하위 폴더 선택을 안내한다. 기본 제외 항목은 숨김 파일·폴더, .git, node_modules이며 UI에 제외 규칙을 안내한다. 취소 가능한 진행 상태를 보여주고 일부 파일의 읽기 실패가 전체 연결 실패로 번지지 않게 한다.

검색 대상은 파일명, 상대 경로, 카드 제목과 메모다. 파일 본문 검색은 제외한다. 한글·영문 대소문자·공백을 고려하며 원본 경로는 표시용 정규화와 별도로 보존한다. 결과를 선택하면 해당 카드 위치로 이동하거나 ‘작업면에 놓기’를 제공한다. 결과가 없을 때 입력 내용과 필터 해제를 안내한다.

### FR03 프로젝트 오브제 P0

사용자가 이미지를 선택하면 표지로 설정한다. 기본 표지는 표시 가능한 첫 이미지이며, 이미지가 없으면 프로젝트 이니셜과 선택 가능한 색을 사용한다. 기존 표지 파일이 바뀌거나 없어져도 색과 위치는 유지하며 표지 변경 상태를 알린다. 폴더 새로고침이 사용자의 표지 선택을 덮어쓰지 않는다.

### 인수 기준

- AC01 폴더 선택 취소 3회 후 프로젝트·임시 카드·핸들이 남지 않는다.
- AC02 폴더 두 개를 연결한 뒤 전환해도 각 프로젝트의 자료와 기록이 섞이지 않는다.
- AC03 1,000개 초과 입력과 개별 읽기 실패에서 부분 상태를 표시하고 작업면은 사용할 수 있다.
- AC04 한글 경로, 같은 이름의 다른 폴더, 빈 폴더를 구분하며 불필요한 자동 재연결을 하지 않는다. 디렉터리 입력으로 빈 폴더를 감지하지 못하면 빈 프로젝트를 생성하지 않는다.

## 4 작업면 배치와 자료 확인

### FR04 카드와 영역 편집 P0

작업면은 논리 좌표 2400 × 1600이며 이동과 확대율 50~150%를 지원한다. 최대 카드 100개와 영역 8개를 둔다. 카드 기본 크기는 240 × 180이며 사용자가 180 × 120부터 600 × 600까지 조정할 수 있다. 위치·크기·겹침 순서를 저장한다. 화면 크기 변경은 저장 좌표를 수정하지 않는다.

파일을 끌어놓거나 목록의 ‘놓기’를 누르면 참조 카드가 생성된다. 같은 파일을 다시 놓으면 별도 cardId를 만들고 assetId는 공유한다. 영역 안에 놓인 카드는 zoneId와 영역 내부 좌표를 갖는다. 영역을 옮기면 소속 카드도 이동한다. 영역 삭제 시 카드는 작업면 절대 좌표로 변환해 유지한다. 카드 제거는 참조만 제거하며 세션 내 되돌리기를 제공한다.

### FR05 이유 메모와 다음 행동 P0

카드 제목은 80자, 메모는 2,000자, 다음 행동은 200자로 제한한다. 입력은 일반 텍스트로 저장하며 글자 수와 한도 도달 상태를 표시한다. 한글 조합 입력 중간에 값을 자르거나 저장해 조합을 깨지 않는다. 독립 메모 카드는 파일 없이 생성할 수 있다. 다음 행동 수정은 현재 작업에 반영하며 저장된 과거 장면을 변경하지 않는다.

### FR06 미리보기 P0

기본 보장 형식은 PNG·JPEG·WebP와 UTF-8 일반 텍스트다. 영상·음원은 브라우저 코덱 지원을 확인해 재생하며 자동 재생하지 않는다. PDF는 브라우저 보기와 별도 탭 열기를 제공하되 PDF 페이지·스크롤 위치 복원은 제외한다. Markdown·코드·HTML·SVG는 P0에서 일반 텍스트로 표시해 스크립트 실행을 막는다. Office·한글·디자인 파일은 메타데이터만 제공한다.

영상·음원은 마지막 사용자 재생 위치를 저장하고, 이어갈 때 길이 범위 안으로 보정한다. 잘못된 코덱, 손상 파일, 20MiB 초과 이미지, 2MiB 초과 텍스트, 500MiB 초과 미디어는 제한 안내로 대체한다. 지원하지 않는 형식을 원본과 동일하게 재현한다고 안내하지 않는다. 다운로드가 복사본을 만든다는 점을 표시한다.

### 인수 기준

AC05 새로고침 전후 위치·크기·영역 관계가 동일하다. AC06 같은 파일의 두 카드가 서로 다른 메모를 유지한다. AC07 키보드 ‘영역으로 이동’ 메뉴와 화살표 이동으로 배치를 완료할 수 있다. AC08 영상 재개는 저장 지점의 ±1초 안에서 준비되고 재생 버튼을 눌러야 소리가 난다. AC09 악성 HTML과 미지원 파일도 전체 앱을 중단시키지 않는다.

## 5 자동 저장과 장면 이어가기

### FR07 현재 작업 자동 저장 P0

입력·이동이 끝난 후 800ms 이내에 저장을 시작하고 마지막 변경 후 2초 이내에 완료하는 것을 성능 목표로 한다. 위치 이동의 최종 값과 한글 조합 완료 값을 저장한다. UI는 저장 중, 저장됨, 저장 실패를 구분한다. IndexedDB 트랜잭션 완료 후에만 ‘저장됨’을 표시한다. 페이지 종료 직전 이벤트만을 저장 수단으로 사용하지 않는다.

### FR08 여기서 멈추기와 수동 장면 P0

‘여기서 멈추기’는 대기 중 편집을 반영하고 현재 작업, 장면, 마지막 중단 장면 참조를 하나의 트랜잭션으로 저장한다. 성공 후 책상으로 이동한다. 실패 시 입력 대화상자를 유지하고 재시도한다. 중복 클릭은 하나의 요청 ID로 처리해 장면을 한 번만 생성한다. 장면 메뉴의 ‘현재 장면 남기기’는 같은 상태를 기록하되 책상으로 이동하지 않는다.

장면에는 카드·영역·메모·다음 행동·선택 카드·보기 위치·미디어 재생 위치와 당시 파일 메타데이터를 저장한다. 원본 내용과 다른 앱의 편집 상태는 저장하지 않는다. 프로젝트당 장면 200개를 지원한다. 한도에 도달하면 내보내기와 명시적 삭제를 안내하며 과거 기록을 자동으로 지우지 않는다.

### FR09 재방문과 과거 장면 이어가기 P0

책상의 ‘이어서 시작’은 가장 최근에 저장된 현재 작업을 연다. 명시적 중단 없이 닫아도 마지막 자동 저장 상태를 복원한다. 마지막 중단 장면보다 현재 작업이 새로우면 ‘중단 이후 변경 있음’을 표시한다. 폴더 권한을 얻기 전에도 배치와 메모는 보여준다.

재개 요약은 마지막 선택 카드와 이유, 다음 행동, 중단 이후 변경 여부를 함께 보여주고, 파일이 바뀌거나 접근할 수 없으면 그 상태를 명시한다. 사용자가 요약에서 카드를 선택하면 저장된 작업면 위치로 이동한다. 파일을 읽을 수 없어도 이유 메모와 다음 행동은 남는다. 요약을 닫거나 다시 열어도 작업면 데이터는 바뀌지 않는다. 이 경험은 기존 자료를 다시 찾는 데 그치지 않고 첫 유효 작업까지 이어지는지 11장에서 검증한다.

과거 장면은 읽기 전용으로 열린다. ‘이 장면에서 이어가기’를 누르면 현재 작업을 안전 장면으로 저장한 뒤 선택 장면의 사본을 현재 작업으로 만든다. 두 동작은 원자적으로 실행한다. 기존 장면은 변경하지 않는다. 안전 장면 공간이 없거나 저장에 실패하면 전환을 중단한다. ‘현재 작업으로 돌아가기’는 읽기 전용 열람만 종료한다.

### 인수 기준

AC10 저장 완료 뒤 브라우저를 다시 열어도 마지막 확정 상태가 복원된다. AC11 저장 실패에서는 중단 완료 화면으로 이동하지 않는다. AC12 중단 버튼 연속 클릭이 장면을 중복 생성하지 않는다. AC13 과거 장면 이어가기 전 상태가 안전 장면에 남고, 같은 기능으로 돌아갈 수 있다. AC14 장면 생성 뒤 카드 편집이 과거 장면의 메모와 위치를 바꾸지 않는다.

## 6 데이터 모델과 저장 규칙

### 핵심 데이터 구조

- Project는 id, name, createdAt, updatedAt, coverAssetId, coverColor, deskPosition, rootRefId, lastPausedSceneId를 갖는다. ID는 UUID로 발급한다.
- RootReference는 id, projectId, sourceMode, rootName, directoryHandle, lastScanAt을 갖는다. sourceMode는 handle 또는 input이다. 핸들은 지원 환경의 IndexedDB에만 저장하고 백업에서는 제외한다.
- Asset은 id, projectId, relativePath, displayName, kind, size, lastModified, availability를 갖는다. availability는 unknown, available, changed, missing, permissionRequired다.
- Workspace는 projectId, revision, zones, cards, nextAction, viewport, selectedCardId, mediaPositions, updatedAt을 갖는다. 프로젝트당 현재 작업은 하나다.
- Zone은 id, title, x, y, width, height다. Card는 id, assetId 또는 null, title, note, zoneId 또는 null, x, y, width, height, zIndex를 갖는다.
- Scene은 id, projectId, title, type, createdAt, sourceRevision, snapshot, assetManifest를 갖는다. snapshot은 Workspace의 깊은 복사본이며 assetManifest는 당시 경로·크기·수정 시각이다.

### 식별과 불변성

Asset.id는 내용이나 수정 시각이 바뀌어도 유지한다. 같은 프로젝트에서 같은 상대 경로가 다시 발견되면 기존 assetId를 재사용하고 메타데이터를 갱신한다. 이동·이름 변경은 자동 확정하지 않고 명시적 재연결로 처리한다. Card.id와 assetId를 분리해 같은 파일에 다른 의미를 붙일 수 있게 한다.

파일 크기와 수정 시각 비교는 변경 신호이며 내용이 동일하다는 증거가 아니다. 장면 열람에서는 해당 장면의 메타데이터와 현재 값을 비교한다. 과거 파일명은 장면에 보존하고, 현재 연결 파일이 다르면 이전 경로와 새 경로를 함께 표시한다.

### 저장소와 트랜잭션

IndexedDB stores는 projects, roots, assets, workspaces, scenes, settings, events로 구성한다. assets에는 projectId와 relativePath의 복합 고유 인덱스를 두고 scenes에는 projectId와 createdAt 인덱스를 둔다. 스키마 버전은 1부터 시작한다. File, object URL, 디코딩된 미디어는 메모리 수명으로 관리하며 장기 데이터에 포함하지 않는다.

자동 저장은 프로젝트 revision을 비교해 갱신한다. 같은 프로젝트의 다른 탭은 읽기 전용으로 열고, Web Locks 지원 시 쓰기 잠금을 사용한다. 지원하지 않을 때도 트랜잭션 내 revision 비교로 충돌 쓰기를 막는다. 충돌 시 덮어쓰지 않고 다시 불러오기와 현재 메타데이터 내보내기를 제공한다.

### 보존 원칙

장면 삭제와 프로젝트 삭제는 관련 수량을 보여준 후 실행한다. 원본 파일에 대한 삭제 API는 사용하지 않는다. 장면에만 남은 파일 참조도 프로젝트 제거 전까지 유지한다. 수정·복원 실패가 발생하면 기존 트랜잭션을 취소하고 마지막 성공 revision을 유지한다.

## 7 재연결과 파일 변경 처리

### FR10 권한 복구 P0

앱 진입 시 저장 핸들의 권한 상태를 확인한다. 권한이 없으면 배치·메모를 먼저 복원하고 ‘폴더 다시 연결’을 표시한다. 권한 요청은 사용자의 클릭으로 실행한다. 저장 핸들이 있어도 이후 방문의 권한을 보장하지 않는다. 핸들 보관과 접근 권한의 구분은 기술 참고자료 2를 따른다.

디렉터리 입력 모드는 세션 이후 실제 파일을 다시 선택해야 한다. 폴더를 재선택하기 전에는 마지막 메타데이터만 표시하며 미리보기를 만들지 않는다. 동일한 폴더명만으로 자동 승인하지 않고 상대 경로의 일치·누락·새 파일 수를 보여준 뒤 사용자 확인으로 연결을 확정한다.

### FR11 새로고침과 누락 파일 P0

작업면 진입과 명시적 ‘폴더 새로고침’에서 범위 내 자료를 재검사한다. OS 파일 변경의 실시간 감시는 이번 범위에 포함하지 않는다. 파일을 열 때도 최신 메타데이터를 확인한다. 변경 시 ‘장면 저장 이후 파일 변경됨’을 표시하고 현재 원본을 보여준다.

스캔이 완전히 끝난 경우에만 해당 범위에서 발견되지 않은 파일을 missing으로 판단한다. 스캔 취소·접근 실패·한도 초과로 확인하지 못한 파일은 unknown을 유지한다. 파일 누락이 카드나 메모의 자동 삭제로 이어져서는 안 된다.

### FR12 파일 경로 다시 연결 P0

사용자는 누락 카드에서 ‘다른 파일로 연결’을 누르고 현재 프로젝트에서 읽을 수 있는 자료를 고른다. 크기·이름·수정 시각은 후보 추천에만 사용한다. 확인 후 동일 assetId의 경로를 갱신하며 그 파일을 공유하는 카드 수와 과거 장면에도 현재 연결이 적용됨을 알린다. 다른 폴더가 필요하면 프로젝트 루트를 먼저 재연결한다.

### 상태별 사용자 안내

permissionRequired는 ‘폴더 접근을 허용하면 파일을 다시 볼 수 있어요’, missing은 ‘파일을 찾지 못했어요. 배치와 메모는 남아 있어요’, changed는 ‘저장 당시와 다른 파일일 수 있어요. 현재 원본을 보고 있어요’로 안내한다. unknown은 마지막 확인 시각과 재검사 행동을 보여준다.

### 인수 기준

AC15 권한 거부 상태에서도 메모와 위치를 읽을 수 있다. AC16 파일 삭제·이동 후 카드가 남고 재연결 시 기존 메모가 유지된다. AC17 이름이 같은 다른 루트를 조용히 연결하지 않는다. AC18 중단된 스캔이 기존 파일을 일괄 누락 처리하지 않는다. AC19 과거 장면은 현재 원본과의 차이를 표시하며 파일 내용 복구 버튼을 제공하지 않는다.

## 8 구현 구조와 기존 코드 전환

### 프런트엔드 구조

기존 apps/web의 React·TypeScript·Vite 구성을 유지한다. 화면 계층은 DeskPage, WorkspacePage, SceneViewer, StorageSettings로 나눈다. 도메인 계층은 ProjectService, AssetService, WorkspaceService, SceneService, BackupService를 둔다. 저장소 접근과 브라우저 파일 접근은 각각 Repository와 FileGateway로 분리해 UI에서 직접 호출하지 않는다.

FileGateway는 폴더 선택, 권한 확인, 파일 목록 수집, File 조회를 담당한다. 순차 스트리밍으로 메타데이터를 수집하고 화면에 필요한 미리보기만 만든다. 전체 원본을 메모리에 읽거나 서버에 보내지 않는다. 중단 가능한 스캔과 제한된 동시 미리보기 작업으로 반응성을 유지한다.

### 내부 동작 계약

- connectProject는 사용자 선택을 받아 프로젝트와 루트 참조를 반환한다. 취소는 cancelled로 구분하며 예외 토스트를 만들지 않는다.
- scanAssets는 진행 수, 신규·변경·누락 후보와 complete 여부를 반환한다. complete가 거짓이면 누락을 확정하지 않는다.
- saveWorkspace는 projectId, expectedRevision, 변경 상태를 받고 새 revision을 반환한다. 불일치는 conflict로 처리한다.
- pauseWorkspace는 대기 편집, nextAction과 requestId를 받아 장면 생성과 현재 작업 저장을 원자적으로 수행한다.
- continueFromScene은 현재 revision을 확인하고 안전 장면 생성과 현재 작업 교체를 하나의 트랜잭션에서 수행한다.
- importBackup은 검증·미리보기 후 새 ID로 프로젝트 사본을 생성한다. 기존 프로젝트를 덮어쓰지 않는다.

### 현재 코드에서 재사용할 부분

2026년 10월 4일 확인한 코드에서 fileSystem.ts는 폴더 선택, 확장자 분류와 하위 파일 수집을 제공한다. App.tsx는 파일 목록·폴더 카드와 기본 미리보기를 제공한다. 이러한 부분을 분리해 재사용하되 새 제품의 인수 기준으로 다시 검증한다.

현재 파일 ID는 경로·수정 시각·크기로 구성되어 있어 수정 후 참조가 달라질 수 있다. Asset UUID로 교체한다. 현재 useState 중심 상태는 재실행 복원을 제공하지 않으므로 Repository 기반 저장으로 전환한다. 검색·필터·장식용 메뉴는 구현 여부를 확인하고 실제 동작이 없는 컨트롤은 새 화면에 노출하지 않는다.

### 제공 방식

백엔드 API는 P0에 필요하지 않다. HTTPS 정적 배포를 전제로 하며 데이터는 같은 브라우저 프로필과 origin에 귀속된다. 도메인 변경 전 백업을 안내한다. URL 직접 진입을 지원하도록 호스팅의 SPA 경로 처리를 설정한다. 서비스 워커 기반 완전 오프라인 재실행은 P1로 둔다.

## 9 백업과 개인정보 보호

### FR13 메타데이터 내보내기와 가져오기 P0

백업 파일은 .folduct.json이며 schemaVersion, exportedAt, projects, assets, workspaces, scenes를 포함한다. 원본 파일, 디렉터리 핸들, 미리보기 Blob, object URL과 이벤트 기록은 제외한다. 가져온 프로젝트에는 다시 폴더를 연결해야 한다. 내보내기 완료가 원본 자료 백업을 의미하지 않는다고 안내한다.

가져오기는 10MiB 상한, UTF-8 JSON 파싱, 버전, 자료형, 문자열 길이, 프로젝트·카드·장면 수, ID 참조와 좌표의 유한값을 검증한다. 상대 경로에는 상위 경로 이동과 절대 경로를 허용하지 않는다. 잘못된 입력이나 미지원 상위 버전은 기존 데이터를 수정하지 않고 거절한다. 읽은 객체를 실행 가능한 코드나 HTML로 취급하지 않는다.

검증 후 프로젝트 수와 장면 수, 필요한 재연결 수를 보여준다. 확정 시 모든 ID와 참조를 새로 매핑해 사본으로 원자적 저장한다. 12개 프로젝트 한도를 초과하면 가져오기 대상 선택을 요청한다. 내보낸 뒤 가져온 사본의 배치·메모·장면이 동일한지 회귀 시험한다.

### FR14 저장소 상태와 복구 P0

첫 실제 장면 저장 이후 브라우저의 영속 저장을 요청할 수 있으나 허용을 보장하지 않는다. 공간 부족 시 저장 실패를 표시하고 현재 메모리 상태를 메타데이터로 내보낼 수 있게 한다. 이전에 저장된 정상 상태는 유지한다. 브라우저 데이터 삭제·프로필 변경·기기 교체 시 자동 복구되지 않음을 저장 관리에서 설명한다. 저장 수명 제약은 기술 참고자료 3을 따른다.

### 데이터 보호와 안전한 렌더링

기본 동작에서 파일 내용·이름·상대 경로·메모를 원격 서버로 전송하지 않는다. 원격 분석 SDK, 세션 녹화, 외부 웹폰트와 외부 이미지 요청을 P0에서 사용하지 않는다. 폰트와 아이콘은 앱 번들 또는 시스템 리소스로 제공한다. 배포 서버가 앱 접속 로그를 남길 수 있다는 점은 파일의 로컬 처리와 구분한다.

입력 텍스트는 이스케이프하고 HTML·SVG를 실행하지 않는다. 원격 링크의 자동 미리보기는 만들지 않는다. CSP는 앱 자원·필요한 blob 미디어만 허용하도록 구성하고 임의 네트워크 연결을 차단한다. object URL은 선택 변경·프로젝트 종료 때 해제한다. local-first는 별도의 암호화 저장을 뜻하지 않으며 공유 컴퓨터 사용자에게 브라우저 프로필 분리를 안내한다.

AC20 백업 왕복 후 참조 관계가 보존된다. AC21 악성·손상 백업은 데이터 변경 없이 거절된다. AC22 파일 열람·메모·저장 시 네트워크에 파일 관련 정보가 포함되지 않는다.

## 10 품질 요구사항과 실패 처리

### 성능 기준

검증 기준 장비는 RAM 8GB 이상 데스크톱, 로컬 SSD와 최신 안정판 Chrome으로 정하고 실제 사양을 기록한다. 자료 1,000개, 작업면 카드 100개와 장면 200개를 기준 데이터로 사용한다. 첫 메타데이터 목록 표시 3초 이내, 메타데이터 작업면 재개 2초 이내를 목표로 한다. 사용자 권한 응답과 미디어 디코딩 시간은 각각 별도 기록한다.

카드 이동은 기준 장비에서 중앙값 50fps 이상, 검색 반응은 p95 200ms 이하를 목표로 한다. 자동 저장은 30회 대표 입력에서 p95 2초 이하를 목표로 한다. 탐색 중 전체 원본 내용을 미리 읽지 않고 썸네일 동시 생성은 최대 4개로 제한한다. 1차 구현 후 같은 데이터로 측정하고 초과 원인을 기록한다.

### 접근성과 조작

모든 주요 행동은 키보드로 실행할 수 있어야 한다. Tab 이동, 선택 표시, 대화상자의 초점 유지·복귀, Escape 취소를 제공한다. 카드 이동은 방향키 10px, Shift 조합 1px와 영역 선택 메뉴를 제공하며 텍스트 편집 중에는 가로채지 않는다. 동작 상태는 색 외에 글자와 아이콘으로 표시한다. 본문 대비 4.5대 1을 목표로 하고 동작 줄이기 설정을 따른다.

### 실패 시 동작

- 저장 공간 부족은 저장 실패 표시와 재시도·내보내기를 제공한다. 확정되지 않은 상태를 저장 완료로 표시하지 않는다.
- 파일 읽기 실패는 해당 카드만 제한하고 배치와 메모 편집을 유지한다.
- 폴더 선택 취소는 기존 상태를 유지한다. 권한 요청 실패는 자동 반복하지 않는다.
- 손상된 장면은 불러오기를 중단하고 현재 작업을 유지한다. 다른 장면과 백업 접근은 제공한다.
- 다른 탭과 충돌하면 편집을 잠그고 현재 변경의 내보내기 또는 최신 상태 불러오기를 제공한다.
- 미저장 상태에서 이동하면 저장을 먼저 시도한다. 실패하면 이동을 멈추고 명시적 선택을 받는다. 갑작스러운 프로세스 종료로 마지막 미확정 변경은 잃을 수 있다.

### 품질 인수 기준

AC23 마우스 없이 연결 이후 배치·메모·중단·재개를 완료한다. AC24 100개 카드에서 저장·검색·이동 목표를 측정한다. AC25 동시 탭 충돌이 조용한 덮어쓰기를 일으키지 않는다. AC26 저장 실패와 스키마 전환 실패가 기존 정상 데이터를 손상시키지 않는다. AC27 Chromium과 제한 모드 각각에서 재연결 동작을 검증한다.

## 11 사용자 검증과 측정 정의

### 검증 설계

문제 인터뷰 5명 후, 8~12명의 디자인·미디어 전공 학생이 참여하는 탐색 실험을 진행한다. 참여자별로 유사 난도의 두 과제를 준비해 기존 도구 방식과 Folduct를 교차 배정한다. 첫 작업 후 2~3일 간격으로 재개하고, 순서·과제 차이·권한 재연결 여부를 기록한다. 모집과 일정이 충족되지 않으면 결과를 사용성 점검으로 한정해 해석한다.

경쟁 제품과의 차별화 검증은 Eagle을 실제로 사용하는 참여자의 기존 작업 방식을 먼저 관찰한다. Eagle에 없는 기능을 가정하거나 참가자에게 낯선 사용법을 강요하지 않는다. 동일한 ‘며칠 뒤 작업 재개’ 과제에서 자료를 찾은 시점뿐 아니라 선택 이유를 확인하고 첫 유효 작업을 시작한 시점까지 측정한다. 별도 소수 관찰 결과는 탐색 근거로 보고하며 제품 우위의 증거로 일반화하지 않는다.

### 지표와 목표

재시작 시간은 프로젝트 접근 시작부터 정해진 자료와 다음 행동을 확인하고 첫 유효 작업을 시작하기까지다. 진행자가 관찰 기준으로 판정한다. 도구별 중앙값뿐 아니라 참여자별 변화율의 중앙값을 보고하며 감소 목표는 30%다. 5분 안에 재개하지 못하면 실패로 기록하고 성공 사례 시간에서 조용히 제외하지 않는다.

재개 성공률은 전체 시도 중 도움 없이 올바른 자료와 행동으로 시작한 비율이며 목표는 80%다. 중단 기록 비용은 중단 대화상자 진입부터 저장 성공까지의 중앙값으로 목표는 15초다. 첫 사용 시간은 폴더 선택 시작부터 카드 3개와 이유 메모 1개가 저장될 때까지이며 목표는 3분이다. 첫 배치 시간과 세션 전체 관리 시간도 보조 기록으로 남긴다.

### 앱 내부 측정

자동 수집만으로 실제 작업 재개 성공을 판단하지 않는다. 앱은 동의한 실험 모드에서 project_connect_started, project_connect_succeeded, card_created, pause_started, pause_saved, resume_clicked, workspace_restored, reconnect_required, save_failed 이벤트를 로컬에 기록한다. timestamp, 무작위 세션 ID, durationMs, errorCode와 항목 수만 포함한다. 파일명·경로·메모·실제 프로젝트 제목은 제외한다.

실험 이벤트는 별도 내보내기를 통해 참여자가 제공하며 기본 원격 전송은 없다. 로컬 이벤트는 최대 30일 보관 후 정리하고 언제든 지울 수 있게 한다. 전달받은 실험 데이터의 보관 기간과 녹화 여부는 모집 안내에서 별도 동의받는다. 운영에 필수인 사용자 메모와 실험 로그를 혼합하지 않는다.

### 판단 규칙

재시작 시간이 줄고 기록 부담이 목표 안에 들면 반복 사용 실험으로 진행한다. 재시작은 빨라지지만 기록이 번거로우면 기본 배치와 중단 입력을 단순화한다. 개선이 없으면 카드·장면 기능을 늘리기 전에 사용자의 실제 중단 상황과 필요한 단서를 다시 조사한다. 결과 보고에는 참여자 수, 누락, 실패, 장비와 과제 조건을 함께 적는다.

## 12 개발 순서와 출시 인수

### 단계별 완료 조건

1단계는 Project·Asset 모델, Repository, 폴더 연결과 책상을 완성한다. AC01~04로 연결·분리·수집 한도를 확인한다. 2단계는 작업면, 카드·영역·메모·미리보기와 자동 저장을 구현하고 AC05~10을 통과한다.

3단계는 중단 기록, 장면 열람·이어가기, 안전 장면, 권한·파일 재연결을 구현하고 AC11~19를 통과한다. 4단계는 백업·가져오기, 저장 실패·충돌 처리, 접근성과 성능을 검증해 AC20~27을 통과한다. 5단계는 실험 지표 수집을 점검하고 사용자 비교 검증을 진행한다.

### 검증 방법

자동 검증은 식별자 유지, 스냅샷 불변성, 원자적 저장·실패 롤백, revision 충돌, 백업 검증·ID 재매핑에 집중한다. 브라우저 통합 검증은 첫 연결부터 중단·새로고침·재개와 과거 장면 이어가기를 다룬다. 실제 OS 파일 변경, 브라우저 권한 철회, 디렉터리 입력 폴백, 코덱 실패와 키보드 조작은 수동 검증 기록을 남긴다.

출시 조건은 모든 P0 요구사항과 AC01~27 충족, 원본 쓰기 없음, 저장 완료 기록의 유실 결함 없음, 허위 복구 표현 없음이다. 사용자 효과 목표 미달은 숨기지 않고 검증 결과로 보고한다. 기능 출시 가능 여부와 제품 가설의 성공 여부는 별도로 판단한다.

### 시연 시나리오

시연용 폴더에서 자료 3개를 놓고 이유 메모를 작성한다. 다음 행동을 남겨 중단한 뒤 앱을 다시 열어 복원을 확인한다. 이전 장면에서 이어가며 안전 장면 생성을 보여주고, 파일 하나의 이동을 재현해 메모가 남는지 확인한다. 마지막에는 메타데이터 백업과 원본 파일의 차이를 설명한다. 실제 사용자 자료를 공개 시연에 사용하지 않는다.

### 개발 착수 시 확인할 사항

실제 팀 구성과 제출 기한, 테스트 장비, 배포 origin, 실험 참여자 모집 가능 여부를 확인한다. 확인 전에는 6주 실행안과 본 문서의 한도를 기본값으로 사용한다. 새로운 요구가 들어오면 핵심 흐름에 미치는 영향과 P0 일정 증가를 검토해 범위를 갱신한다.

본 버전은 웹 구현을 위한 요구사항 정의다. 문서 작성만으로 기능 구현·배포·사용자 효과 검증이 완료된 것은 아니다.

## 13 기술 참고자료와 결정 기록

### 브라우저 동작의 근거

아래 공식 문서는 2026년 10월 4일 확인했다. API 호환성과 권한 정책은 출시 검증 때 다시 확인한다. 문서의 카드 수, 화면 크기, 시간 목표, 저장 정책은 Folduct의 설계 결정이며 공식 API가 보장하는 값이 아니다.

1. MDN Window showDirectoryPicker는 보안 컨텍스트와 사용자 동작이 필요하며 폭넓은 브라우저 공통 기능이 아니다. 이 제약에 따라 FR01의 클릭 기반 요청과 제한 모드를 설계했다.

https://developer.mozilla.org/en-US/docs/Web/API/Window/showDirectoryPicker

2. Chrome for Developers The File System Access API는 핸들을 IndexedDB에 저장할 수 있음을 설명한다. 핸들 저장과 이후 권한 유지가 동일하지 않으므로 FR10은 매번 권한 상태를 확인한다.

https://developer.chrome.com/docs/capabilities/web-apis/file-system-access

3. MDN Storage quotas and eviction criteria는 브라우저별 저장 한도, 데이터 제거와 영속 저장의 차이를 설명한다. FR13·14의 명시적 백업과 저장 실패 처리는 이 제약을 고려한 제품 요구사항이다.

https://developer.mozilla.org/en-US/docs/Web/API/Storage_API/Storage_quotas_and_eviction_criteria

### 프로젝트 내부 참고

기획의 기준은 folduct-project-plan-v1.0.md와 이번 대화에서 합의한 ‘중단한 작업의 맥락을 되찾는 책상’이다. 기존 memory-desk-concept-overview.md는 공간 기억 개념의 배경이며, folduct-web-architecture.md는 이전 파일 탐색기 방향의 구조를 설명한다. 새 제품의 범위가 충돌할 때는 이 PRD를 우선 적용한다.

구현 현황은 apps/web/src/App.tsx, apps/web/src/fileSystem.ts, apps/web/src/types.ts와 apps/web/package.json을 기준으로 확인했다. 데스크톱 앱과 이전 기획서 파일은 이번 문서 작성 과정에서 수정하지 않았다.

### 주요 결정

- 웹 중심과 로컬 메타데이터 저장을 채택해 별도 계정 없이 핵심 경험을 검증한다.
- 장면은 맥락의 기록으로 한정하며 파일 버전 보관은 분리한다.
- 책상과 작업면은 2차원으로 구현하고 키보드·목록 대안을 제공한다.
- 자동 저장과 안전 장면을 통해 중단 버튼 누락·과거 상태 전환에서도 현재 기록을 보호한다.
- 원본 재연결과 메타데이터 백업을 P0로 포함해 재방문 경험을 완성한다.
