# Folduct 방 돌보기 단계별 구현 프롬프트

작성일: 2026-10-18 · 대상: Folduct 프로젝트 루트의 `apps/web` · 기준 문서: [PRD 2.0](./folduct-prd-v2.0.md) FR15~19, AC28~40 · 사용 방식: 한 번에 한 단계의 프롬프트만 Cursor Agent에 붙여 넣기

이 문서는 ‘돌보는 작업방’, 즉 손대지 않은 물건이 쓰러지고, 일주일마다 **실제 폴더 안 정리 상자 폴더로 파일을 옮기는** 기능을 개발 대화로 옮기는 지시서다. 기존 [Cursor 단계별 구현 프롬프트](./cursor-vibe-implementation-prompts.md)의 공통 작업 계약을 그대로 따르고, 아래 ‘방 돌보기 추가 계약’을 더한다.

> **2026-10-18 진행 상태:** Claude Code로 C1~C5와 ‘차 한 잔’ 시각 언어를 구현했다(진행 기록 참고). C0의 실제 로컬 폴더 실험, C6(물건 크기·방 용량), C7(실패·접근성 마감)이 남았다. 아래 프롬프트는 남은 단계와 재검증에 그대로 쓸 수 있다.

## 0. 사용 방법

1. Cursor에서 Folduct 프로젝트 루트를 연다(docs와 apps/web이 함께 보이게).
2. 처음에는 **C0 점검**만 붙여 넣는다. C0 결과가 “실제 Chrome에서 파일 이동 가능”일 때만 C3 이후로 간다.
3. 각 단계의 보고에서 실제 완료·미검증·다음 행동을 확인하고 다음 단계 하나만 보낸다. 여러 단계를 합치지 않는다.
4. 실제 파일을 옮기는 C3~C5는 **반드시 테스트용 임시 폴더**로 검증한다. 실제 작업 폴더로 시험하지 않는다.
5. `docs/02-progress.md`의 최신 상태가 이 문서보다 우선한다. 기존 5단계 검증이 남아 있으면 그 기록을 먼저 확인한다.

## 1. 기술 전제 — 웹에서 되는 것과 안 되는 것

C0에서 실제 브라우저로 다시 확인한다. 아래는 지시서 작성 시점의 조사 결과이며 확정 사실로 취급하지 않는다.

| 하고 싶은 일 | 웹에서 | 방법·한계 |
| --- | --- | --- |
| 폴더 안 파일 목록·용량·수정 시각 보기 | 가능 | 이미 구현됨(`folderScan.ts`). 1,000개·깊이 10 한도 |
| 프로젝트 폴더 안에서 파일 옮기기·이름 바꾸기 | **Chrome·Edge만 가능** | `FileSystemFileHandle.move(디렉터리, 새이름)`. Safari·Firefox는 불가 |
| 새 폴더 만들기 | Chrome·Edge만 가능 | `getDirectoryHandle(name, { create: true })` |
| 휴지통으로 보내기 | **불가** | 웹 API에 휴지통이 없다. `removeEntry`는 영구 삭제라 **쓰지 않는다** |
| 쓰기 권한 | 사용자 클릭이 있어야 요청 가능 | `requestPermission({ mode: "readwrite" })`. 앱이 스스로 몰래 받을 수 없다 |
| 앱이 꺼져 있을 때 정리 | 불가 | 앱을 열고 사용자가 ‘정리하기’를 누를 때만 실행 |
| Finder에서 파일 위치 열기 | 불가 | ‘경로 복사’로 대체 |
| 실시간 파일 변경 감지 | 이번 범위 밖 | ‘폴더 새로고침’으로 다시 스캔 |
| 홈 폴더 전체, 시스템 폴더 | 브라우저가 막을 수 있음 | 프로젝트 폴더 단위로 연결 |

**결론:** Chrome·Edge에서는 “정리 상자 폴더로 실제 이동”과 “제자리로 실제 복원”까지 가능하다. 실제 삭제는 Folduct가 하지 않고, 사용자가 Finder에서 상자 폴더를 비운다. 지원하지 않는 브라우저나 폴더 입력 방식(`sourceMode: "input"`)으로 연결한 방은 Folduct 안에서만 상자로 옮기고, 그 사실을 화면에 적는다.

## 2. 방 돌보기 추가 계약 — C 단계 전체에 적용

기존 공통 작업 계약의 “원본 쓰기·이동·삭제 금지”는 PRD 2.0 4장 기준 1에 따라 아래처럼 바뀐다. **이 계약에 없는 파일 변경은 여전히 금지다.**

1. **허용되는 원본 변경은 두 가지뿐이다.** 프로젝트 루트 아래 `_Folduct 정리상자` 폴더를 만드는 것, 그리고 파일을 그 폴더로 옮기거나 원래 자리로 되돌리는 것이다. 삭제(`removeEntry`), 내용 쓰기(`createWritable`), 루트 밖으로 옮기기, 폴더 통째로 옮기기는 하지 않는다.
2. **사용자 확인 뒤에만 옮긴다.** 옮길 파일 목록을 먼저 보여주고, 사용자가 ‘정리하기’를 눌렀을 때 그 클릭 안에서 쓰기 권한을 요청한다. 권한이 거부되면 아무것도 옮기지 않는다.
3. **덮어쓰지 않는다.** 옮길 위치에 같은 이름이 있으면 `이름 (2).확장자`처럼 새 이름을 쓴다. 되돌릴 때 원래 자리에 다른 파일이 있으면 되돌리지 않고 이유를 알린다.
4. **기록 먼저, 이동은 그다음.** 파일마다 “이동 중” 기록을 IndexedDB에 먼저 남기고, 이동이 성공하면 자료 경로와 기록을 “상자 안”으로 바꾼다. 앱이 중간에 꺼져도 다음 실행 때 기록을 보고 파일이 실제로 어디 있는지 확인해 맞춘다.
5. **파일 하나의 실패가 나머지를 망치지 않는다.** 실패한 파일은 제자리에 남기고, 결과에 “n개 옮김, m개 실패(이유)”를 보여준다.
6. **카드·메모·배치는 지우지 않는다.** 상자에 간 파일의 카드는 방에서 숨길 뿐, 메모와 원래 위치를 그대로 갖고 있다.
7. **실제 파일 변경을 검증할 때는 임시 폴더만 쓴다.** 자동 테스트는 메모리 가짜 디렉터리로 하고, 실제 브라우저 검증은 테스트용 폴더를 새로 만들어 쓴다.

### 코드 구조 결정 — C0 지시서 작성 시점에 코드를 읽고 정한 것

C0에서 실제 코드와 다르면 진행 기록에 남기고 사용자에게 알린다.

- **돌보기 상태는 카드 스키마에 넣지 않는다.** `domain/validation.ts`의 `readCard`는 정확한 키 목록(`exactKeys`)으로 카드를 검사하고, 장면 스냅샷도 같은 검사를 거친다. 카드에 필드를 더하면 장면·백업·검증이 한꺼번에 흔들린다. 대신 기존 `settings` 스토어에 방마다 `care:<projectId>` 기록을 둔다. 스키마 버전을 올릴 필요가 없다.
- **방을 쓴 날은 이미 있다.** `folductRepository.ts`의 `markActivity`가 `activity:<projectId>`에 최근 30일 작업일을 남긴다. 방치 판정은 이것을 재사용한다.
- **손댄 시각은 한 곳에서 잡는다.** `components/WorkspaceEditor.tsx`의 `apply(next)`가 모든 편집이 지나는 길목이다. 이전·다음 작업면을 비교하는 순수 함수(`domain/care.ts`)로 손댄 카드를 계산한다.
- **파일 경로 갱신은 새 저장소 메서드로 한다.** 자료(`Asset`)의 `relativePath`를 바꾸는 메서드가 아직 없다. `assets` 스토어는 `[projectId, relativePath]` 고유 인덱스를 가지므로 충돌 검사와 함께 한 트랜잭션에서 바꾼다.
- **권한 함수는 모드를 받게 바꾼다.** `gateways/fileGateway.ts`의 `readPermission`·`askPermission`은 지금 `"read"`로 고정되어 있다. 처음 폴더를 고를 때는 계속 읽기 권한만 요청한다.
- **상자 폴더 이름은 `_Folduct 정리상자`다.** 점(.)으로 시작하면 Folduct 스캔에서 빠지고 Finder에서도 숨겨지므로 쓰지 않는다. 이 폴더 안 파일은 자료 목록에 ‘정리 상자’ 표시와 함께 나온다.

### 돌보기 기록 형식

```ts
// settings 스토어, key = `care:${projectId}`
type CareRecord = {
  key: string;
  enabled: boolean;            // 새 방 true, 기존 방 false
  resting: boolean;            // 쉬는 중
  tiltAfterDays: number;       // 3
  fallAfterDays: number;       // 7
  budgetBytes: number | null;  // C6
  touched: Record<string, number>;   // cardId → 손댄 시각
  pinned: string[];                  // 고정한 cardId
  boxed: Record<string, BoxEntry>;   // assetId → 상자 기록
};

type BoxEntry = {
  state: "moving-in" | "boxed" | "moving-out" | "virtual";  // virtual = 실제 파일은 그대로, Folduct 안에서만 상자
  fromPath: string;    // 원래 상대 경로
  boxPath: string;     // `_Folduct 정리상자/...` 상대 경로
  at: number;
};

// settings 스토어, key = "care:sweep"
type SweepRecord = { key: "care:sweep"; lastSweepAt: number | null; weekday: number };
```

## 3. 단계별 프롬프트

### C0. 점검과 브라우저 파일 이동 실험 — 앱 기능 변경 없음

### C1. 손댄 시각 기록과 방치 판정 — 화면 변경 없음

진입 조건: C0에서 코드 구조 결정이 확인됨. 관련: PRD FR15, AC29·AC30.

~~~text
방 돌보기 C1만 구현해줘. 지시서 2장의 추가 계약과 CareRecord 형식, PRD FR15를 먼저 읽어줘.

만들 것:
1. domain/care.ts (순수 함수, IndexedDB·React 의존 없음)
   - touchedCardIds(prev: Workspace, next: Workspace): string[]
     카드의 x·y·width·height·zoneId·title·note가 바뀐 카드, 
     그리고 selectedCardId가 새로 바뀐 카드(미리보기 열기)를 손댄 것으로 센다.
     viewport·zIndex만 바뀐 것, 카드 삭제는 세지 않는다.
   - careStage(input): "normal" | "tilted" | "fallen"
     입력: 손댄 시각, 지금, 방을 쓴 날 목록(YYYY-MM-DD), 기준일(3/7), 
     고정 여부, 쉬는 중 여부, 자료 상태(availability), 원본 lastModified.
     규칙: 손댄 뒤 기준일이 지났고, 그 사이 '방을 쓴 날'이 하루 이상 있을 때만 기울어짐/쓰러짐.
     고정·쉬는 중·missing·permissionRequired·원본이 손댄 뒤 수정됨 → 항상 normal.
2. 저장소: settings 스토어의 care:<projectId> 읽기/쓰기 메서드 (지시서 형식 그대로).
   기록이 없으면 enabled=false인 기본 기록을 반환한다.

3. WorkspaceEditor의 apply()에서 touchedCardIds로 손댄 카드를 계산해 기록한다.
   readOnly(장면 열람)일 때는 기록하지 않는다. 기록 실패가 자동 저장을 막지 않게 해줘.

테스트(vitest):
- 호버·스크롤·확대·zIndex 변경은 손댄 것으로 안 셈, 이동·크기·메모·선택은 셈 (AC29)
- 방을 14일 동안 안 열면 쓰러지지 않음, 그 사이 다른 카드를 만진 날이 있으면 쓰러짐 (AC30)
- 고정·쉬는 중·누락·원본 최근 수정 예외
- 날짜 경계(자정 전후, 로컬 시간) 한 건

화면은 바꾸지 마. 테스트·빌드·진행 기록을 갱신하고 C2 진입 여부를 보고해줘.
~~~

### C2. 기울어짐·쓰러짐 표시, 고정·쉬는 중

진입 조건: C1 완료. 관련: PRD FR15·FR19, 4장 기준 3·4, AC28·AC37.

~~~text
방 돌보기 C2만 구현해줘. PRD 4장 기준 3·4, FR15 표시 규칙, FR19를 먼저 읽어줘.

만들 것:
1. 방(WorkspaceEditor)의 카드에 careStage 표시:
   - 기울어짐: 약 8° 회전 + 라벨 "3일째 그대로"
   - 쓰러짐: 눕힌 모양 + 라벨 "7일째 그대로 · 다음 정리 때 상자로"
   - 회전은 CSS transform 표시 효과로만. 저장 좌표·크기·zIndex를 바꾸지 마 (AC28).
   - prefers-reduced-motion이면 회전 없이 라벨만. 라벨은 스크린리더에서도 읽히게 (AC37).
   - 카드 클릭·드래그 영역이 회전 때문에 틀어지지 않는지 확인해줘.
~~~

## 4. 각 단계 결과를 확인하는 법

- Cursor의 “완료” 보고만 믿지 말고, C4·C5는 **Finder에서 테스트 폴더를 직접 열어** 파일이 실제로 옮겨졌는지 본다.
- `npm run build` 통과는 타입 검사일 뿐이다. 권한 창, 실제 이동, 새로고침 뒤 상태는 브라우저에서 확인해야 한다.
- 7일을 기다리지 않고 시험하려면 C4의 집 상단 ‘주간 정리’ 버튼을 쓴다. 쓰러짐 상태를 빨리 보려면 방 설정의 기준일을 0~1일로 낮춘다.
