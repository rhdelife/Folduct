# Folduct 웹앱 단계별 구현 지시서

버전 1.0 · 기준 문서 `docs/folduct-web-prd-v1.0.md` · 구현 대상 `apps/web`

## 공통 구현 규칙

### 제품의 중심

사용자가 폴더를 연결하고 필요한 자료를 배치한 뒤 선택 이유와 다음 행동을 남긴다. 다시 방문했을 때 같은 맥락을 확인해 작업을 이어간다. 프로젝트 오브제는 구분을 돕고 작업면은 자료 사이의 역할과 관계를 보여준다.

장면은 배치·메모·참조·보기 상태의 기록이다. 파일 내용의 과거 버전이나 외부 편집기 상태를 복구하지 않는다. 과거 장면에서도 파일 미리보기는 현재 원본을 참조하며 차이를 표시한다.

### 작업 범위와 보존

- `apps/web`의 기존 React·TypeScript·Vite 구성을 바탕으로 구현한다. `apps/desktop`을 변경하지 않는다.
- 작업 전 현재 변경을 확인하고 관련 없는 사용자 변경을 되돌리지 않는다. 전체 저장소 초기화나 무조건적인 파일 교체를 하지 않는다.
- 원본 폴더는 사용자가 고른 범위만 읽는다. 파일 쓰기·이동·삭제, 자동 업로드와 OS 전체 탐색은 구현하지 않는다.
- P0에 서버·계정·클라우드 동기화·AI 요약·3D 엔진을 추가하지 않는다.
- 데모와 실제 데이터를 분리한다. 테스트는 전용 브라우저 프로필과 임시 폴더를 사용한다.
- 기존 기획서·PRD를 임의로 재작성하지 않는다. 명세의 결함을 발견하면 변경 이유와 영향 범위를 기록한다.

### 구조와 의존성

UI, 도메인 동작, IndexedDB 저장, 파일 접근을 분리한다. 모든 로직을 `App.tsx`에 계속 추가하지 않는다. 아래 구성은 권장 구조이며 작은 프로젝트에 맞게 합치거나 나눌 수 있다.

```text
apps/web/src/
  pages/           DeskPage WorkspacePage SceneViewer StorageSettings
  components/      카드 영역 파일목록 미리보기 대화상자 저장상태
  domain/          모델 검증 한도 좌표 변환 순수 함수
  services/        Project Asset Workspace Scene Backup 서비스
  repositories/    IndexedDB 접근과 트랜잭션
  gateways/        브라우저 파일 접근과 권한
  hooks/           UI 상태와 도메인 연결
  tests/           중요한 도메인 동작 검증
```

필요한 라이브러리는 목적과 기존 의존성으로 해결하기 어려운 이유를 기록하고 최소한으로 추가한다. 패키지를 추가했다면 잠금 파일도 갱신한다. 버전이나 API를 추측하지 말고 설치된 버전과 공식 문서를 확인한다. 스타일링만을 위해 프로젝트 프레임워크를 전환하지 않는다.

### 매 단계의 작업 완료 방식

1. 해당 단계의 PRD 항목과 기존 구현을 확인한다.
2. 실제로 작동하는 기능을 구현한다. 껍데기 버튼이나 성공 토스트로 완료를 대신하지 않는다.
3. 해당 단계의 의미 있는 검증과 `apps/web`의 `npm run build`를 실행한다.
4. `02-progress.md`에 변경, 확인한 결과, 제한과 다음 시작점을 기록한다.
5. 관련 AC 항목을 `03-acceptance.md`에서 갱신하고 근거를 남긴다.
6. 구현한 기능, 검증 결과, 미검증 사항, 다음 단계만 간결히 보고한다.

단계 종료는 모든 기능의 출시 완료를 의미하지 않는다. 테스트 환경 제약으로 남은 항목은 명시적으로 미검증 처리한다. 다음 단계가 그 항목에 의존하면 먼저 해결한다. 네이티브 권한 창은 자동화용 모의 데이터 검증과 실제 사용자 동작 검증을 구분한다.

## 0단계 기존 프로젝트 점검

**목표:** 현재 코드의 출발점과 구현 순서를 확인한다. 앱 기능 변경은 아직 시작하지 않는다.

**작업:**

- 적용되는 저장소 지침과 현재 변경 상태를 확인한다.
- 새 기획서와 PRD를 읽고 이전 데스크톱 기획과 분리한다.
- `App.tsx`, `fileSystem.ts`, `types.ts`, `sampleData.ts`, `styles.css`, `package.json`과 빌드 설정을 확인한다.
- 기준 빌드와 가능하면 기존 화면을 실행해 재사용 가능한 부분을 기록한다.
- 수정 시각 기반 파일 ID, 휘발성 화면 상태, 미구현 컨트롤과 외부 자원 요청을 점검한다.
- 구현 전 확인할 모호한 정책을 기록한다. 특히 백업 가져오기의 10MiB 상한과 지원 최대 데이터의 내보내기 크기가 양립하는지 검토 대상으로 남긴다.

**완료 기준:** 기준 빌드 결과, 재사용·교체 대상, 실행 환경과 기술적 쟁점이 진행 기록에 있다. 미완성 기능을 완료로 표시하지 않았다.

**Cursor 프롬프트:**

```text
handoff/cursor-web-v1.0/01-build-steps.md의 0단계만 수행해줘.
새 기획서와 PRD, 현재 코드와 사용자 변경을 확인하고 기준 빌드를 실행해줘.
앱 기능을 변경하기 전에 재사용·교체 대상과 명세의 쟁점을 정리해줘.
02-progress.md를 갱신하고 구현 시작에 필요한 근거를 보고해줘.
```

## 1단계 데이터 모델과 저장 기반

**선행:** 0단계 점검 완료. **관련 PRD:** 6장과 8장, FR07~09의 저장 규칙.

**목표:** 파일을 실제로 연결하기 전에 데이터가 안정적으로 저장되는 기반을 만든다.

**작업:**

- Project, RootReference, Asset, Workspace, Zone, Card, Scene 타입을 정의한다.
- Project·Asset·Card·Scene 식별자는 안정적인 UUID로 발급한다. 파일 수정 시각을 식별자로 쓰지 않는다.
- 논리 좌표, 영역 내부·절대 좌표 변환, 데이터 한도를 순수 함수로 분리한다.
- IndexedDB stores와 인덱스, 스키마 버전 1, repository 인터페이스를 구현한다.
- 프로젝트 생성과 초기 작업면 저장, expectedRevision을 사용하는 현재 작업 저장을 구현한다.
- UI와 영구 데이터에서 File·Blob URL·디렉터리 핸들의 용도를 구분한다. 핸들은 별도 저장 경로로 처리한다.
- 스키마 불일치 시 데이터베이스를 삭제해 초기화하지 않고 안전한 오류를 반환한다.
- 테스트 환경을 실제로 구성하고 식별자 유지, 잘못된 입력 거절, revision 충돌과 트랜잭션 실패 롤백을 검증한다.

**완료 기준:** 샘플 데이터를 저장한 뒤 저장소 인스턴스를 다시 열어도 같은 상태가 읽힌다. 실패·충돌에서 기존 정상 데이터가 유지된다. 실제 테스트 실행 명령이 package.json에 있다.

**프롬프트:**

```text
단계별 지시서의 1단계를 구현해줘. 새 PRD 6장과 8장을 기준으로
도메인 타입, 안정적 ID, IndexedDB repository, revision 검증을 만들어줘.
중요한 저장 동작과 실패 롤백을 테스트하고 빌드를 확인해줘.
화면 완성도를 넓히기보다 다음 단계가 사용할 저장 기반을 완성해줘.
진행 기록과 검증 근거를 갱신하고 이번 단계 결과를 보고해줘.
```

## 2단계 폴더 연결과 개인 책상

**선행:** 1단계 저장 기반. **관련:** S01, FR01~03, AC01~04.

**목표:** 사용자가 실제 폴더를 연결해 여러 프로젝트를 구분할 수 있게 한다.

**작업:**

- /desk와 /projects/:projectId 경로, 첫 진입과 잘못된 주소 안내를 만든다.
- 사용자 클릭에서 읽기 전용 폴더 선택을 실행하고 API 미지원 시 디렉터리 입력으로 폴백한다.
- 기존 폴더 수집을 진행·취소·부분 실패를 표현하는 gateway로 정리한다.
- 파일 1,000개, 깊이 10과 제외 규칙을 적용한다. 전체 원본을 한꺼번에 읽지 않는다.
- 폴더 선택과 프로젝트 생성 확정을 구분해 취소 시 빈 레코드가 남지 않게 한다.
- 같은 이름의 다른 폴더를 자동 병합하지 않는다. 동일 핸들을 확인할 수 있으면 기존 프로젝트로 안내한다.
- 프로젝트 이름·대표 이미지·색·책상 위치를 저장한다. 책상 크기는 1440 × 900, 프로젝트 한도는 12개다.
- 위치 이동과 목록 대안을 제공한다. 첫 배치와 사용자 지정 위치를 구분해 새로고침 시 재정렬하지 않는다.
- 데모 체험은 별도 저장 공간을 사용하며 데모 종료·초기화가 실제 프로젝트를 지우지 않게 한다.

**완료 기준:** 두 폴더를 연결하고 프로젝트를 전환해도 파일과 메타데이터가 섞이지 않는다. 책상 위치·이름은 새로고침 후 유지된다. 재선택 전 미리보기가 제한되는 경우 그 상태를 정확하게 보여준다.

**검증:** AC01~04, 첫 화면·빈 폴더·같은 이름 폴더·수집 한도·취소·부분 읽기 실패. 네이티브 폴더 선택이 불가능한 환경에서는 실제 검증 필요 항목을 남긴다.

**프롬프트:**

```text
단계별 지시서의 2단계를 구현해줘. 1단계 저장소를 사용해 실제 폴더 연결,
API 미지원 폴백, 여러 프로젝트와 개인 책상을 만들어줘.
읽기 전용 접근, 취소·부분 실패, 안정적인 ID와 사용자 지정 배치를 지켜줘.
AC01~04와 새로고침 복원을 검증하고 진행 기록을 갱신해줘.
```

## 3단계 작업면과 이유 메모 및 자동 저장

**선행:** 2단계 프로젝트와 자료. **관련:** S02, FR04·05·07, AC05~07·10.

**목표:** 실제 자료를 놓고 이유를 적을 수 있는 작업면을 완성한다.

**작업:**

- 왼쪽 자료 목록, 중앙 작업면, 선택 시 열리는 오른쪽 미리보기·메모 패널을 만든다.
- 작업면 2400 × 1600, 확대율 50~150%, 이동과 영역 8개·카드 100개 한도를 구현한다.
- 파일 끌어놓기와 ‘작업면에 놓기’, 독립 메모 생성, 카드 선택·이동·크기 변경·앞뒤 순서를 구현한다.
- 영역 기본값과 이름 변경, 카드의 영역 소속, 영역 이동·삭제 시 좌표 보존을 구현한다.
- 같은 Asset을 두 번 놓으면 Card는 별도 생성하고 이유 메모를 독립적으로 저장한다.
- 카드 제거는 참조만 제거하고 세션 내 되돌리기를 제공한다. 원본 제거 행동과 혼동하지 않게 표현한다.
- 메모·제목·다음 행동의 길이 제한과 한글 조합 입력을 처리한다.
- 화면 좌표를 확대율·이동값으로 논리 좌표에 변환한다. 창 크기 변경은 영구 좌표를 바꾸지 않는다.
- 자동 저장 상태와 debounce를 연결하고 최신 변경 순서를 보장한다. 이전 비동기 응답이 새 상태를 덮어쓰지 않게 한다.
- 파일명·경로·카드 제목·메모 검색, 결과 카드로 이동, 키보드 이동과 영역 선택 메뉴를 구현한다.

**완료 기준:** 카드 3개와 메모를 배치해 저장된 뒤 새로고침하면 위치·크기·메모·영역이 유지된다. 선택되지 않은 오른쪽 패널이 작업면을 상시 가리지 않는다. 저장 실패를 성공으로 표시하지 않는다.

**검증:** 확대율이 다른 상태에서 이동, 영역 삭제 후 위치, 같은 파일의 두 메모, 빠른 연속 입력과 한글 조합, 이동 종료 직후 저장, 키보드 배치. AC10은 현재 작업 복원 범위를 먼저 검증하고 장면은 5단계에서 추가한다.

**프롬프트:**

```text
단계별 지시서의 3단계를 구현해줘. 실제 자료를 작업면에 배치하고
이유 메모를 남기며 위치와 상태가 자동 저장되게 해줘.
영역·확대·키보드 조작·동일 파일의 독립 카드·한글 입력까지 구현해줘.
PRD의 FR04, FR05, FR07과 관련 AC를 검증하고 결과를 기록해줘.
```

## 4단계 미리보기와 보기 상태

**선행:** 3단계 카드와 선택 상태. **관련:** FR06, AC08~09.

**목표:** 자료를 확인하면서 판단 메모를 남길 수 있게 한다.

**작업:**

- 기존 미리보기를 별도 컴포넌트로 분리해 PNG·JPEG·WebP, UTF-8 텍스트를 제공한다.
- 브라우저가 재생할 수 있는 영상·음원과 PDF 보기·별도 열기를 연결한다.
- Markdown·코드·HTML·SVG는 P0에서 일반 텍스트로 처리한다.
- Office·한글·디자인 파일은 지원 범위를 정확하게 표시한다. 다운로드는 복사본 생성이라고 안내한다.
- 손상 파일·코덱 미지원·크기 한도·파일 읽기 실패를 카드 단위로 처리한다.
- 영상·음원의 마지막 재생 위치를 Workspace에 저장하고 metadata 로드 뒤 길이 안으로 보정해 복원한다.
- 자료를 전환할 때 이전 비동기 읽기 결과가 새 자료에 섞이지 않게 한다.
- object URL을 선택·프로젝트 수명에 맞춰 해제한다. 자동 재생과 원격 콘텐츠 로드를 하지 않는다.

**완료 기준:** 영상 재생 위치와 선택 자료가 재방문 시 복원되며 재생은 사용자 동작으로만 시작한다. 미지원 파일 하나가 작업면 전체를 막지 않는다.

**검증:** AC08~09, 짧아진 영상의 재생 위치 보정, 연속 자료 전환, 크기 제한, 악성 HTML·SVG의 비실행. PDF 내부 페이지 복원은 이번 범위에 넣지 않는다.

**프롬프트:**

```text
단계별 지시서의 4단계와 PRD FR06을 구현해줘.
지원 형식의 실제 미리보기, 미지원 안내, 미디어 재생 위치 저장·복원,
파일 전환 중 비동기 경합과 object URL 정리를 처리해줘.

```

## 5단계 여기서 멈추기와 장면 이어가기

**선행:** 3단계 저장과 4단계 보기 상태. **관련:** S03~05, FR08~09, AC10~14.

**목표:** 프로젝트의 핵심인 중단·재방문·이어가기 경험을 끝까지 완성한다.

**작업:**

- 다음 행동 200자와 장면 이름 60자 대화상자, 기본 이름, 입력 생략과 취소를 구현한다.
- 대기 중 편집을 반영한 뒤 Workspace·Scene·Project.lastPausedSceneId를 하나의 트랜잭션에서 저장한다.
- 네트워크·미디어 읽기 같은 장시간 비동기 처리를 DB 쓰기 트랜잭션 안에 끼워 넣지 않는다. 저장할 데이터는 먼저 준비하고 revision을 재확인한다.
- 중복 클릭은 버튼 잠금과 요청 ID로 멱등 처리한다. 실패하면 입력을 보존하고 화면을 이동하지 않는다.
- 수동 장면 저장과 장면 목록, 읽기 전용 장면 열람을 구현한다.
- 과거 장면 이어가기는 현재 상태의 안전 장면 저장과 선택 장면 사본 적용을 원자적으로 처리한다.
- 과거 장면과 현재 작업이 참조를 공유해 함께 바뀌지 않게 한다. 원본 파일 사본은 만들지 않는다.
- 책상의 ‘이어서 시작’은 마지막 확정 Workspace를 연다. 장면 이후 수정이 있으면 최신 현재 작업을 우선한다.
- 장면 200개 한도와 안전 장면 생성 실패를 처리한다. 안전 장면을 만들 수 없으면 현재 작업을 교체하지 않는다.

**완료 기준:** 작업 중단 → 앱 재실행 → 같은 자료·메모·다음 행동 확인이 된다. 과거 장면에서 이어가도 직전 작업이 안전 장면에 남는다. 파일 복구 기능처럼 안내하지 않는다.

**검증:** AC10~14. 강제 저장 실패, 연속 클릭, 장면 생성 직전 편집, 과거 장면 열람 후 취소, 장면 한도, 장면 불변성과 두 동작의 전체 롤백.

**프롬프트:**

```text
단계별 지시서의 5단계를 구현해줘. 여기서 멈추기, 수동 장면,
장면 목록·읽기 전용 열람, 안전 장면을 남기는 이어가기를 완성해줘.
저장 원자성, 중복 요청, 과거 장면 불변성과 최신 현재 작업 우선 규칙을 지켜줘.
AC10~14를 실제 흐름과 실패 테스트로 검증하고 결과를 기록해줘.
```

## 6단계 권한 재연결과 파일 변경

**선행:** 5단계 장면 저장·열람. **관련:** FR10~12, AC15~19·27.

**목표:** 실제 컴퓨터에서 파일이나 권한이 바뀌어도 맥락이 남게 한다.

**작업:**

- 앱 진입 시 저장 핸들의 권한을 확인하고 클릭을 통한 복구를 제공한다.
- 권한이 없어도 Workspace와 Scene의 메모·배치를 먼저 보여준다.
- 폴백 환경에서는 재선택한 폴더와 기존 상대 경로의 일치·누락·신규 수를 확인시킨다.
- 스캔 완료 여부와 확인 범위를 구분한다. 취소·한도·권한 실패를 누락 파일로 오판하지 않는다.
- 파일 수정 시 같은 Asset ID를 유지하고 장면 manifest 대비 변경을 표시한다.
- 삭제·이동 시 빈 자리와 메모를 유지한다. 실제 파일 찾기와 명시적 연결 변경을 제공한다.
- 연결 변경이 같은 Asset을 쓰는 카드와 과거 장면에 영향을 준다는 점을 확인시킨다.
- 연결할 경로가 이미 다른 Asset으로 등록되어 있으면 복합 고유 인덱스와 충돌하지 않도록 병합 규칙을 정의한다. 모든 카드·장면의 참조를 일관되게 유지하고 임의 메모 삭제를 금지한다.
- 경로·크기·수정 시각 일치만으로 파일 내용 동일성을 확정하지 않는다.

**완료 기준:** 권한 거부와 파일 누락에도 메모·배치가 남고, 재연결 후 같은 기록으로 파일을 확인할 수 있다. 다른 폴더를 자동 연결하지 않는다.

**검증:** AC15~19·27. 테스트 전용 폴더의 수정·이동·삭제, 불완전 스캔, 동명 폴더, 공유 Asset의 재연결, 브라우저 재시작과 디렉터리 입력 폴백. 사용자 원본을 테스트 목적으로 변경하지 않는다.

**프롬프트:**

```text
단계별 지시서의 6단계와 PRD FR10~12를 구현해줘.
권한·폴더 재연결, 파일 변경과 누락 표시, 명시적 경로 연결을 완성해줘.
불완전 스캔과 같은 이름 폴더를 안전하게 처리하고 안정적 ID를 유지해줘.
AC15~19, AC27을 검증하되 실제 브라우저에서 확인 못 한 부분은 구분해 기록해줘.
```

## 7단계 백업과 저장소 복구

**선행:** 6단계 재연결과 참조 규칙. **관련:** S06, FR13~14, AC20~21·26.

**목표:** 사용자가 앱의 맥락 데이터를 보관하고 다시 가져올 수 있게 한다.

**먼저 해결할 명세 쟁점:** PRD의 가져오기 상한은 10MiB인데 카드·메모·장면이 많으면 정상 백업도 이를 넘을 수 있다. 구현 전에 최대 크기 샘플로 크기를 측정한다. 스스로 내보낸 정상 백업을 다시 가져올 수 없는 상태는 완료로 인정하지 않는다. 용량 정책 또는 분할 포맷을 바꾸어야 한다면 영향과 권장안을 사용자에게 설명하고 확정한 명세를 기록한다. 문서에 없는 데이터 삭제나 기록 축약으로 한도를 맞추지 않는다.

**작업:**

- .folduct.json 내보내기를 구현하며 핸들·원본·Blob·object URL·이벤트 로그를 제외한다.
- 내보낼 root 연결 정보에는 sourceMode·rootName 등 재연결에 필요한 비민감 구조만 포함하고 새 rootRefId에 연결되게 한다. 폴더명·메모 자체도 개인 정보일 수 있음을 고려해 원격 전송하지 않는다.
- 스키마 버전, 타입, 길이, 수량, ID 참조, 유한 좌표, 상대 경로를 검증한다.
- 가져올 항목과 필요한 재연결 수를 확인시킨 뒤 ID를 모두 재매핑해 사본을 만든다.
- Project.coverAssetId·rootRefId·lastPausedSceneId, Workspace·Scene의 Card·Zone·Asset·선택 카드·미디어 위치 등 모든 참조를 함께 변환한다.
- 저장소 공간 부족과 영속 저장 요청 거부를 처리하고, 현재 메모리 상태도 백업할 수 있게 한다.
- 프로젝트·장면 삭제는 수량 안내와 확인 후 메타데이터만 제거한다. 마지막 장면 참조와 삭제 후 목록 상태를 정리한다.
- 데이터 마이그레이션은 실패 시 기존 데이터 보존을 검증한다. 데이터베이스 강제 삭제로 오류를 숨기지 않는다.

**완료 기준:** 백업을 새 브라우저 저장 공간에 가져오고 폴더를 다시 연결하면 위치·메모·장면이 보존된다. 손상·미지원 백업은 기존 데이터를 바꾸지 않는다. 삭제가 원본 파일에 영향을 주지 않는다.

**검증:** AC20~21·26, 최대 지원 데이터 왕복, ID 중복·참조 누락·프로토타입 오염용 키·상위 경로·손상 JSON, 중간 실패 전체 롤백, 최신 장면 삭제, 원본 미포함 확인.

**프롬프트:**

```text
단계별 지시서의 7단계를 진행해줘. 먼저 백업 용량 한도 쟁점을 실제 데이터로
확인하고 해결 정책을 기록해줘. 범위 변경 결정이 필요한 부분은 근거와 권장안을 알려줘.
명세 안에서 진행 가능한 메타데이터 백업·검증·사본 가져오기·저장 실패 복구를 구현해줘.
모든 참조 ID를 정확히 재매핑하고 AC20~21, AC26을 검증해줘.
```

## 10단계 Vercel 배포 준비

**선행:** 9단계 결과 확인. **기준:** [Vercel 배포 지시서](04-vercel-deployment.md).

**목표:** 정적 웹앱의 배포 설정과 운영 절차를 준비한다. 실제 공개 배포와 구분한다.

**작업:**

- 실제 Git 루트와 연결 대상 저장소 기준으로 Root Directory를 정한다. 현재는 `apps/web` 자체가 별도 Git 루트다.
- 기존 설정을 보존하면서 Vite 빌드, 출력 폴더, SPA fallback과 운영 보안 정책을 준비한다.
- 고정 운영 주소, 로컬 데이터 보관과 주소 변경 시 백업·재연결 안내를 정리한다.
- 로컬에서 검증 가능한 빌드·정적 서비스 항목을 확인하고, 원격 검증은 배포 대기로 남긴다.
- 실제 배포는 별도 실행 요청 후 Preview → DEP 검증 → 운영 승인 → 운영 배포 순으로 진행한다.

**완료 기준:** 설정·로컬 검증·운영 안내·미검증 DEP 항목이 기록되어 있다. 배포하지 않았으면 URL이나 성공 상태를 작성하지 않는다.

**프롬프트:**

```text
04-vercel-deployment.md를 읽고 10단계 배포 준비를 수행해줘.
기존 사용자 변경을 보존하면서 설정과 로컬 빌드를 확인하고,
SPA 직접 접속·운영 보안·고정 주소와 로컬 데이터 이전 안내를 준비해줘.
원격 검증은 미검증으로 표시하고 진행 기록에 다음 실행 절차를 남겨줘.
계정 연결·프로젝트 생성·커밋·푸시·실제 배포는 아직 하지 마.
```
